# Blanc v1.32.0 release — October 13, 2026

Status: published and independently verified; public v1.32.0 is the baseline.
The adjacent public-feed updater handoffs (v1.31.0 → v1.32.0) on macOS and on
Windows are pending owner confirmation.

Scope: a minor release with these app changes merged since v1.31.0.

- Arc Spaces import (F45, #705, with #707): Bring Your Tabs reads Arc's
  sidebar file without changing it and brings the Spaces the user picks, with
  pinned tabs, Today tabs and folders as tab groups. With Blanc Patron each
  becomes a space; without it, each opens in its own window. Arc's top-row
  Favorites can go into a Favorites folder named Arc. On Linux the user
  chooses a copied `StorableSidebar.json`. The real-sidebar evidence its
  release gate requires is
  [F45 Arc Spaces import: real-sidebar evidence](../evidence/f45-arc-import-real-sidebars-2026-10-12.md):
  every step passed on macOS, Windows and Linux (Choose file…), with the
  deviations and coverage limits listed there (no Intel Mac, no x64 Windows).
- Interface localization (F44, Phases 2a–9, #675 through #723): Blanc's
  interface is available in German, Spanish, French and Portuguese (Brazil),
  machine-translated, and follows a matching system language.
- Named Workspaces is renamed Blanc Spaces, with `/space` and the
  `/workspace` alias (#706).
- The 1Password fill setup prompt's **Open Settings** opens Settings at the
  1Password card (#722).
- The browser's links and copy point at blanc.day (#750).
- Fixes: the Windows/Linux shortcuts sheet's "Search && Commands" (#727), and
  a second launch now stops at the single-instance lock instead of starting
  up on the running profile (#726).
- 1Password fill on Windows and Linux (#685) and its fixes (#688, #692/#696,
  #693/#700, #701/#702, #728, #733, #739/#770, #740/#771, #741/#772). Windows
  was turned off by #742 and back on by #768 once #735 proved to be a test
  artifact. Both platforms ship enabled and **unannounced**, under the
  2026-10-12 waiver in [the 1Password integration doc](../1password-integration.md):
  the evidence is x64 Blanc and 1Password under Arm emulation in a Windows VM,
  and an ARM64 Linux development build, not a real x64 Windows PC or a
  packaged x64 AppImage. The release notes don't mention it, by the owner's
  decision before the run.
- The fix for this release's blocker (#773, below).

Release notes: [v1.32.0](../press/release-notes/v1.32.0.md). Stable mode,
platforms `mac,windows,linux`, `BLANC_MAC_ARCHES=arm64,x64`, from
`e68974129859d34dfca9fa0d3f2947a7abfd7499` (PR #773).

## Attempts

The release ran twice. Attempt 1 stopped before the tag push, so no tag,
draft or asset existed until attempt 2.

1. **Packaged first-run smoke, real bug.** Launched 03:23 EDT from
   `fbf8953aecdcaefc88a3ff40a9b607786ea0e94c`. The press gate passed (215
   desktop scenarios), both Mac architectures were built and notarized, and
   the fuse, blocker-payload and compliance checks passed. The
   `packaged-filter-failure` case then failed: the start page showed **Retry**
   and **Continue without blocking** under "Preparing blocking…" and the
   preparing message, not "Blocking could not start." and its diagnostic. It
   failed 3 of 3 times against the same signed build, so it was not resumed as
   a flake. A probe of that build showed main reporting `phase: "failed"` and
   a re-render correcting the text; a trace showed why. Since #714 the card's
   title and message carry `data-i18n` keys, and `i18n.js` applied static
   text at `DOMContentLoaded`. On a cold launch main already knows the blocker
   failed, so the page's render landed first and the static pass then
   restored the preparing text. v1.31.0 had no keys on that card.
   **Fix (#773):** `bootstrap` applies static text at most once per element,
   and before page code reads a string, so no later pass overwrites rendered
   text. Its two unit tests fail against the old file. The same smoke passed
   3 of 3 on a signed unpacked build of the fix branch. The owner merged #773
   at 08:01Z; its last check, `desktop (macos-15-intel)`, passed at 08:08Z.
2. **Published.** Launched from `e6897412` and passed everything. The Safari
   Sigstore page's loopback callback timed out, and cosign fell back to its
   manual verification-code flow. The operator's log watcher missed the prompt
   for about 17 minutes because `tr` buffered its pipe; the lesson is
   recorded for future runs. The owner signed in and entered the code, and
   the script verified the bundle against the pinned identity before
   publishing.

app, that passed strict deep `codesign` verification with team XYGUCY4498 and

`CN=Bananify Creative, O=Bananify Creative, L=North Chili, S=New York, C=US`
