# Blanc v1.49.0 release — November 13, 2026

Status: published and independently verified at 18:21 UTC on November 13,
2026, from `ac3d6d96018827222c885858282b8c8290668dd0`. The release run
stopped after its tag and draft existed, because the native run's Linux job
failed a smoke check. The owner approved rerunning that job against the same
tag, twice; the second rerun passed, and the rest of `release.sh` ran by hand
in its own order. The macOS and Windows updater handoffs from v1.48.0 are
pending.

## Scope

A feature release on the same runtime as v1.48.0, castLabs' Electron for
Content Security `45.2.1+wvcus`. Checked on November 13, 2026, castLabs'
newest stable release was still `v45.2.1+wvcus`; the only newer one was the
`v46.0.0-alpha.7+wvcus` pre-release.

Release notes: [v1.49.0](../press/release-notes/v1.49.0.md), prepared in #1492.

- **Added:** a refreshed Mahjong, its three tile sets, and its match trail and
  board-cleared celebration (#931, #1489, notes from #1490).
- **Changed:** the closed Island no longer shows the current Space's mark;
  the ⌘L panel's Spaces button shows it instead (#1450, #1454). The address
  field reads **Search or type URL**.
- **Fixed:** windows a page opens on its own after **Continue** on a
  certificate warning for a local or private-network address (#1478).

**What's New:** `https://blanc.day/whats-new/1.49` (#1493) leads with the
refreshed Mahjong and adds the Spaces button. The owner signed off on its
text and media, and it was deployed from `ac3d6d96` (Cloudflare deployment
`45614cc7`, Production on `main`) before the release started. Its captures
came from a development build of that commit. `release.sh`'s page check
passed before the build and again before Sigstore.

**Not checked before release** (both stay open in
[unreleased.md](../press/release-notes/unreleased.md)): Mahjong by hand in a
packaged build, and the pop-out fix against a real local console such as
Proxmox's.

## The release run

`npm run release` ran in a native Terminal.app window from that worktree, with
`BLANC_RELEASE_OPERATOR=terminal`, `BLANC_RELEASE_MODE=stable`,
`BLANC_RELEASE_RUNTIME=ecs`, `BLANC_RELEASE_PLATFORMS=mac,windows,linux` and
`BLANC_MAC_ARCHES=arm64,x64`. The `==> Preparing` line read `runtime=ecs`.

1. `op signin` went through the 1Password desktop integration, the press gate
   passed, and both notarized Mac builds were made.
2. Every packaged check passed on the signed build: ECS identity, archive pin,
   uBO record and fuse wire; hardened fuses; byte-identical blocker payloads;
   compliance payloads; first run; release regressions; Workspace quit/restart
   recovery; both live favicon matrices; migration from v1.48.0; and public
   ECS acceptance (installed uBO, file isolation, and protected playback with
   `passed: true` on arm64, `PLATFORM_SOFTWARE_VERIFIED`).
3. The tag `v1.49.0` was pushed and the authenticated draft created with the
   complete macOS asset set.
4. Native run
   [`43477339123`](https://github.com/bnfy/blanc/actions/runs/43477339123)
   was dispatched. Its Windows job passed every step (Authenticode, ECS
   playback, installed regressions, upload, attestation).
5. Its `linux` job failed at **Verify public ECS file isolation and protected
   playback**, after the build and every packaged-payload, fuse, AppImage,
   capture, Workspace, drawing, protocol and uBO check had passed. The
   Widevine component installed (4.10.3112.0) and a decrypting player was
   created, but the license request to `proxy.widevine.com` was aborted
   (`net::ERR_ABORTED`) and the smoke timed out waiting for the VMP lab's
   status (`Timed out waiting for production VMP verification`). `release.sh`
   printed `Native build failed. Draft remains unpublished.` and exited 1.
   The tag and draft stayed as evidence; neither was deleted or overwritten.

## Recovery

With the tag in place, the release could not be rerun. The owner approved each
step below.

1. **Rerun of the failed job** (`gh run rerun 43477339123 --failed`, attempt
   2): protected playback passed, but **Packaged browser and Settings
   regressions** failed in `packaged-browser-compatibility-smoke.mjs`: typing
   `https://example.com` into a new tab's address field left `h`
   (`late focus cannot replace a typed prefix`). The whole smoke had run about
   three seconds after launch, and the smoke types without waiting for
   browser startup to finish. Nothing in 1.49.0 changed how the address field
   takes focus (the overlay's only changes were the Spaces button's drawing),
   and the same check passed on Windows in this run, on the signed Mac build,
   and on Linux in v1.48.0. It is most likely a race in the smoke rather than
   a release regression, but a real focus slip within seconds of launch has
   not been ruled out.
2. **Second rerun** (attempt 3): every step passed, including the Ubuntu
   22.04 launch and the upload and attestation of `Blanc-1.49.0.AppImage` and
   `latest-linux.yml`. The job set matches v1.47.0's run `42392419003`
   (`ecs-production-*`, `linux-sandbox` and `ecs-native` skipped).
3. The remaining `release.sh` stages ran by hand from a visible Terminal
   window in the release worktree, from a script that copies them verbatim
   and in order (the stable publish branch fixed). It first checked that
   HEAD and the tag were both `ac3d6d96`, the tree was clean, the release
   was still a draft and run `43477339123` had concluded success. Then: the
   draft download, manifest validation (15 artifacts), the SBOM and
   `SHA256SUMS`, the What's New check, the Sigstore sign-in in Safari,
   `cosign verify-blob` against the pinned identity (`Verified OK`), the
   complete manifest check (17 artifacts), upload of the three derived files,
   publication at 18:21 UTC, the logged-out download smoke, and the changelog
   refresh. It exited 0.
