# Blanc v1.44.1 release — October 28, 2026

Status: published and independently verified at 02:32 UTC on October 28, 2026
(the evening of October 27 in the owner's time zone), from
`3b0c000b569ee33a1548dd1b9a60817fae9288a6`. v1.44.1 is the 1.44 feature
release: v1.44.0 was tagged but never published, because it was built on the
wrong runtime (below). The owner confirmed the macOS and Windows updater
handoffs from v1.43.1 on October 28, 2026.

## Scope

The same castLabs Electron for Content Security pin as v1.43.x (`44.9.3+wvcus`,
Chromium 152.0.7977.167), so Widevine playback, uBO's reviewed runtime record
and the owner's runtime waivers in
[the ECS runtime security review](../ecs-runtime-security-review-2026-10-23.md)
carry over unchanged. Release notes: [v1.44.1](../press/release-notes/v1.44.1.md).

- **Added:** Reader Mode; Move to Space; selecting several tabs; Send to
  Device; rules that open links from other apps in a chosen profile or Space
  (and `/route`); Copy Link and Copy Clean Link (and `/copy`); Ctrl+Tab by
  most recent use on Linux and Windows; Vertical tab text size; site icons on
  the Island (#1194).
- **Changed:** switching Spaces names the tabs in the way; Settings → Sync
  shows your devices; pinned tabs always lead the Island's dots, grouped or not
  (#1191, #1192, #1209).
- **Fixed:** Open in Glance from a two-page split; the vertical-tabs menu
  button on Windows and Linux.

Shared Spaces ships in the source but stays hidden in packaged builds
(`isSharedSpacesOffered()` returns `!app.isPackaged`); its restore fix #1204
is included. Enabling it is PR E (#1208), planned for 1.45.

The What's New page for 1.44 (`https://blanc.day/whats-new/1.44`) was live
before the release (#1167, #1171). The site now treats a feature line as
released from its first published version, so the 1.44 page takes 1.44.1's
date and changelog anchor.

## v1.44.0: tagged on the wrong runtime, never published

`v1.44.0` was tagged at `dc501e0da` and a draft created on October 27 by the
seventh attempt. `scripts/release.sh` defaulted `BLANC_RELEASE_RUNTIME` to
`official`, and the launcher never set it, so the press gate, the Mac build,
the packaged checks and the native run all used official Electron 44.9.3
(`runtime=official` in the log, the native ECS jobs skipped). v1.43.0 and
v1.43.1 shipped on ECS, so publishing it would have moved every updater off
Widevine. The owner caught it before publication. Its Linux job had also
failed one packaged check ("late focus cannot replace a typed prefix"), a
focus race that passes elsewhere.

The tag and the unpublished draft (Mac and Windows assets on official
Electron) are kept as evidence, as released versions are immutable. #1206
made the runtime explicit: `release.sh` now refuses to start without
`BLANC_RELEASE_RUNTIME`, and the runbook and releasing-blanc skill name
`runtime=ecs` and the EVS settings.

The earlier 1.44.0 attempts never reached a tag: attempt 1 lost a Glance focus
scenario; attempt 2 lost five ad-blocking scenarios to one renderer crash
(#1180, which led to the harness healing in #1187); the owner stopped
attempt 3; attempt 4 lost three order-dependent scenarios (which led to the
gate's logged rerun in #1196); attempt 5 passed the whole gate, then the
second 1Password prompt (notarization) timed out; the owner stopped attempt 6
to include #1194.

## The castLabs EVS sign-in

ECS releases VMP-sign the Mac builds locally through the castLabs EVS client.
The signed-in client the 1.43 releases used lived under `/private/tmp`, which
macOS had since cleared, and `~/.config/evs/config.json` had never been signed
in. The account name is `anthony-loria` (the email is separate). The owner
reset its password by emailed code and signed in on October 28, 2026. The
client (castlabs-evs 1.3.2, CI's pin) and account files now live in
`~/.config/evs/`, and on the owner's instruction the `ecs-signing`
environment's `EVS_CONFIG_JSON` and `EVS_CACHE_JSON` secrets were refreshed
from them at 00:49 UTC, so Windows signing uses the same sign-in.

## The release runs

- **Launch 1** (21:31 local) stopped at the first 1Password prompt
  (authorization timeout). Nothing was built.
- **Launch 2**, from `3b0c000b5` with `BLANC_RELEASE_RUNTIME=ecs`, logged
  `runtime=ecs`. The press gate passed on its first run: 4,967 unit tests, and
  566 desktop scenarios and 4,916 steps through the acceptance gate with no
  rerun needed, plus the smokes, security audit and site build. Both Mac
  architectures were built, VMP-signed, Developer ID signed and notarized, and
  passed the ECS identity, fuse, blocker-payload, compliance, packaged and ECS
  acceptance checks. The tag and draft followed.
- **Native run `40619758217`:** the `ecs-signing` deployment was approved under
  the owner's release approval (twice, for the rerun too). Linux passed,
  including the Ubuntu 22.04 launch. Windows failed **Verify public ECS file
  isolation and protected playback** on attempt 1: the isolation smoke read
  the page before it had a `<body>` (`Cannot read properties of null (reading
  'append')`), a test race filed as #1210; the test hasn't changed since #1063
  and passed for both 1.43 releases. With the owner's approval, only that job
  was rerun, and attempt 2 passed, including protected playback.
- **Finish:** `release.sh` had exited at the failed native run, so with the
  owner's approval its remaining steps ran by hand, in its order and with its
  commands: download and validate the draft, SBOM and `SHA256SUMS`, a fresh
  Sigstore authorization in Safari, bundle verification against the pinned
  identity and issuer, the complete manifest, upload of the three derived
  assets, publication, the logged-out download smoke and the changelog
  refresh. All passed.

store; it does. The deployed Worker also serves the M16 Space stores
(`spaces`, `closed`, `shared`, per-Space `space-*` stores under the
`AccountQuota` Durable Object), uploaded at 2026-10-27 00:39 UTC under the
owner's Cloudflare account. The owner's October 26 record
