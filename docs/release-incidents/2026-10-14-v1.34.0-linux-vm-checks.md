# Blanc 1.34.0 Linux VM checks — October 14, 2026

Blanc 1.34.0 ships the Linux tab drawing fix ([#798](https://github.com/bnfy/blanc/pull/798)) and two window-close fixes that change how Windows and Linux save tabs ([#814](https://github.com/bnfy/blanc/pull/814), [#817](https://github.com/bnfy/blanc/pull/817)). The affected-machine waiver in [`2026-10-14-linux-tab-drawing-waiver.md`](2026-10-14-linux-tab-drawing-waiver.md) covers "Blanc 1.33.1 only", and 1.33.1 was never released.

This is a release gate record, not a public release record. The v1.34.0 release incident should link here.

## Owner decision

On October 14, 2026, offered the choice between extending that waiver and re-running the checks, the owner chose: "Rerun the Linux VM checks (tab drawing plus close-and-relaunch) on the 1.34.0 candidate instead of extending the waiver." This record does not approve the release, and it does not waive signing, notarization, the press gate, updater handoffs or any other release verification.

- **Sandbox setting:** Ubuntu's default `kernel.apparmor_restrict_unprivileged_userns=1` stops the AppImage from starting, as documented since v1.26.0 in `docs/linux-appimage-troubleshooting.md`. ## Results

### 1. Tab drawing (#798), X11 under Xvfb: pass

- **Method:** `xvfb-run -a node test/desktop/packaged-tab-view-drawing-smoke.mjs` with `BLANC_PACKAGED_EXECUTABLE` pointing at the AppImage. This is the smoke from [#810](https://github.com/bnfy/blanc/pull/810), which the release's Linux job also runs. It turns ad blocking off.
- **Result:** all 4 tab views stayed visible, drew 43 frames in 700 ms and scrolled 400 px. That covers the page active at launch, the other page shown for the first time, the page shown again after Ctrl+Tab, and the tab woken after `/sleep`, which also kept its session storage. Exit 0.

### 2. Tab drawing (#798), native Wayland: pass

- **Method:** the same smoke, run in the VM's GNOME Wayland session with no X display (`DISPLAY` unset). A one-line wrapper launched the AppImage with `--ozone-platform=wayland`. Without that flag, Blanc refused to start with "Missing X server or $DISPLAY". So this run could only draw through Wayland.
- **Result:** all 4 tab views stayed visible, drew 42–43 frames in 700 ms and scrolled 400 px, the woken tab kept its session storage. Exit 0.

### 3. Close the last window with ✕, then relaunch (#814): pass

- **Method:** the close-and-relaunch method from the 1.33.1 record, run in an Xvfb display at 1600×1000 with no window manager. Ad blocking was on, the default.
  1. Launch with two local pages and wait until `session.json` lists both.
  2. Click Blanc's own close button with an X pointer (`xdotool`), with no DevTools connection open.
  3. Wait for every Blanc process to exit, then read `crash-ledger.json` and `session.json`.
  4. Relaunch with the same profile, with a DevTools port used only to read the restored tabs.
  5. Close that window the same way.
- **Close:** all 12 processes exited on their own 118 ms after the click, with status 0. No window was left, and the crash ledger was clean.
- **Saved tabs after ✕:** `session.json` still listed New Tab, "Quit check A" and "Quit check B". On 1.33.1 and v1.33.0 the same step left an empty session.
- **Relaunch:** it restored New Tab, "Quit check A" and "Quit check B", with B active. Closing it exited in 118 ms with status 0, and the session kept its three tabs.
