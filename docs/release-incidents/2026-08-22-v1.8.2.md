# v1.8.2 release verification — 2026-08-22

## Outcome

Blanc v1.8.2 was published to production from source commit `3998b36`.
The release contains signed and notarized macOS artifacts, signed Windows
artifacts, an authenticated Linux AppImage, updater metadata, checksums, an
SBOM, Sigstore verification material, and GitHub provenance attestations.

The macOS updater handoff and public Linux launch checks passed. Windows
artifact and download checks passed, but the final updater installation and
relaunch remain unverified because the Parallels test environment interfered
with process ownership. This is an explicit post-release evidence gap, not a
waiver of a passing Windows updater result and not evidence of a product
regression.

## Release pipeline

- GitHub release: <https://github.com/bnfy/blanc/releases/tag/v1.8.2>
- Native Windows/Linux workflow: run `32587804143`
- Public smoke workflow: run `32588037269`
- The Windows build verified the exact expected Authenticode publisher,
  timestamped signatures, Electron fuses, and packaged files before upload.
- The release pipeline verified packaged ad-block inputs, generated the SBOM
  and checksum manifest, signed the manifest with Sigstore, and published the
  immutable release only after the native jobs completed.

## macOS v1.8.1 to v1.8.2 updater handoff

Packaged public v1.8.1 discovered and downloaded the public v1.8.2 update.
Selecting **Restart Now** invoked the real Squirrel/ShipIt handoff. ShipIt
reported `Installation completed successfully`, installed v1.8.2 into the
same application path, and relaunched it. The resulting bundle reported
v1.8.2 and passed strict deep code-sign verification.

This was an updater handoff initiated inside v1.8.1, not a direct launch of
the v1.8.2 DMG or ZIP.

## Linux v1.8.2 AppImage

Public smoke run `32588037269` downloaded the released AppImage and checksum
manifest, matched the artifact digest, verified GitHub provenance, and
launched the actual AppImage under Xvfb with an isolated profile. It observed
Blanc chrome, the overlay, the start page, and the rendered `v1.8.2` marker.

## Windows evidence gap

Packaged public v1.8.1 downloaded the exact public v1.8.2 installer and showed
the native **Update 1.8.2 downloaded** prompt. Its updater log recorded
`Install on explicit quitAndInstall` and the expected updater arguments after
**Restart Now** was selected. The installed executable nevertheless remained
at v1.8.1 during the observed attempts.

Those attempts were not a clean product test: Parallels Coherence
(`prl_cc.exe`) and later the guest-exec supervisor owned or retained the app
process, and the guest control channel eventually wedged during a reboot.
Because the harness could have prevented the normal quit/install lifecycle,
the result is inconclusive. Do not record it as either a successful handoff or
a confirmed updater defect.

The next release must perform the normal public v1.8.2-to-next Windows handoff
from Blanc itself, including **Restart Now**, installer completion, relaunch,
and installed-version confirmation in a clean desktop session.
