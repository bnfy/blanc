# Blanc v1.48.0 release — November 11, 2026

Status: published and independently verified at 16:14 UTC on November 11,
2026, from `2098dd703c99194a58e5a3e7ec0b39923d2db59b`. The release run stopped
after its tag and draft existed, because the Linux build couldn't install
packages on GitHub's runners. The owner approved a recovery: fix the release
workflow, rebuild Linux alone against the same tag, and run the rest of
`release.sh` by hand in its own order. The macOS and Windows updater handoffs
from v1.47.1 are pending until the owner reports them.

## Scope

A feature release on the same runtime as v1.47.x, castLabs' Electron for
Content Security `45.2.1+wvcus`. On the day castLabs' newest stable release
was still `v45.2.1+wvcus` (November 5); the only newer one was the
`v46.0.0-alpha.7+wvcus` pre-release.

Release notes: [v1.48.0](../press/release-notes/v1.48.0.md), prepared in #1446.

- **Added:** Glance over a split (#1444).
- **Fixed:** WebSockets after **Continue** on a certificate warning for a local
  or private-network address (#1442).

There is no What's New page: the owner put `1.48` in `noPage`, so no site
deploy was needed before the release.

**Not checked before release** (both stay open in
[unreleased.md](../press/release-notes/unreleased.md)): Glance over a split
by hand in a packaged build on any platform (it has run only in the Linux
acceptance suite), and the WebSocket fix against a real local console such as
Proxmox's.

## The release run

`npm run release` ran in a native Terminal.app window from that worktree, with
`BLANC_RELEASE_OPERATOR=terminal`, `BLANC_RELEASE_MODE=stable`,
`BLANC_RELEASE_RUNTIME=ecs`, `BLANC_RELEASE_PLATFORMS=mac,windows,linux` and
`BLANC_MAC_ARCHES=arm64,x64`. The `==> Preparing` line read `runtime=ecs`.

1. `op signin` and the press gate passed, and both notarized Mac builds were
   made.
2. Every packaged check passed on the signed build: ECS identity, archive pin,
   uBO record and fuse wire; hardened fuses; byte-identical blocker payloads;
   compliance payloads; first run; release regressions; Workspace quit/restart
   recovery; both live favicon matrices; migration from v1.47.1; and public
   ECS acceptance (installed uBO, file isolation, and protected playback with
   `passed: true` on arm64, `PLATFORM_SOFTWARE_VERIFIED`).
3. The tag `v1.48.0` was pushed and the authenticated draft created with the
   complete macOS asset set.
4. Native run
   [`43041786515`](https://github.com/bnfy/blanc/actions/runs/43041786515)
   was dispatched. Its Windows job waited at the `ecs-signing` reviewer gate;
   Claude approved it on the owner's standing instruction that their release
   approval covers that click, and the job then passed every step (Authenticode,
   ECS playback, installed regressions, upload, attestation).
5. Its `linux` job failed at **Install AppImage smoke runtime**, after the
   build and every packaged-payload and fuse check had passed:
   `Temporary failure resolving 'azure.archive.ubuntu.com'` (and
   `archive.ubuntu.com`, `security.ubuntu.com`), then apt exit 100. `release.sh`
   printed `Native build failed. Draft remains unpublished.` and exited 1. The
   tag and draft stayed as evidence; neither was deleted or overwritten.

## Recovery

With the tag in place, the release could not be rerun. The owner approved each
step below.

1. **Rerun of the failed job** (`gh run rerun 43041786515 --failed`): the
   same failure, about 10 minutes later.
2. **#1447** pinned the release workflow's `linux` job to `ubuntu-24.04`,
   on the theory that the new Ubuntu 26.04 image was at fault. It merged as
   `39104454` with every required check green; the non-required
   `browser-shortcuts (ubuntu-latest)` had failed at *Install xdotool (Linux)*
   (the same apt failure) and `shared-spaces` was still running, which the owner
   accepted. A Linux-only release run
   [`43048693154`](https://github.com/bnfy/blanc/actions/runs/43048693154)
   (`mode=release`, `platform=linux`, `runtime=ecs`,
   `source_sha=2098dd70…`, against the existing tag) failed the same way on
   `ubuntu-24.04`.
3. **#1449** made both apt steps on the release path (the `linux` job's
   smoke runtime, and the Ubuntu 22.04 job that launches and uploads the
   AppImage) point apt at `http://mirrors.edge.kernel.org/ubuntu/`, with
   `archive.ubuntu.com` as fallback, fail if the Azure host is still
   configured, and retry downloads. It is inline in the workflow because
   release runs check out the tag. It merged as `c223e3e7` on the same terms
   as #1447.
4. Linux-only release run
   [`43052178080`](https://github.com/bnfy/blanc/actions/runs/43052178080)
   passed: the build, every packaged and smoke check, the Ubuntu 22.04 launch,
   and the upload and attestation of `Blanc-1.48.0.AppImage` and
   `latest-linux.yml`. Nothing already on the draft was touched.
5. The remaining `release.sh` stages ran by hand from a visible Terminal
   window in the release worktree, from a script that copies them verbatim
   and in order (the stable publish branch fixed), after checking the commit,
   the tag, the draft state, the Windows job of `43041786515` and run
   `43052178080`: download of the draft, manifest validation, the SBOM and
   `SHA256SUMS`, the What's New check (`noPage`), the Sigstore sign-in in
   Safari, `cosign verify-blob` against the pinned identity (`Verified OK`),
   the complete manifest check, upload of the three derived files, publication
   at 16:14 UTC, the logged-out download smoke, and the changelog refresh.
   It exited 0.

The Windows installer and the Linux AppImage therefore come from two runs of
the same workflow against the same tag and source commit; the Linux one used
the workflow from `c223e3e7`, whose only differences from the original are
#1447 and #1449.

### Correction: #1447's diagnosis

#1447 attributed the Linux failures to the Ubuntu 26.04 image. That was wrong. The cause was that GitHub-hosted runners couldn't resolve Ubuntu's package archives (`azure.archive.ubuntu.com`, `archive.ubuntu.com`, `security.ubuntu.com`) on November 11, 2026, whatever the image version:
- The release's Linux-only run 43048693154, dispatched after #1447, failed at *Install AppImage smoke runtime* on `ubuntu-24.04`.
- CI on PR #1448 (which tried the same pin for the parity-guards jobs) failed at *Install xdotool (Linux)* on image `ubuntu-24.04` 20261101.360.1 (run 43050596262, from 15:43 UTC). In the same `apt-get update`, `packages.microsoft.com` resolved and downloaded normally. #1448 was closed unmerged.
- #1449 fixed the release path by pointing apt at mirrors.edge.kernel.org.

The owner decided on November 11, 2026 to keep #1447's `ubuntu-24.04` pin. v1.47.1's AppImage was built on `ubuntu-24.04` (run 42684721441, November 9). `ubuntu-latest` became 26.04 between then and November 11 (run 43041786515), so the pin keeps the AppImage on the same build OS as every earlier public release.
