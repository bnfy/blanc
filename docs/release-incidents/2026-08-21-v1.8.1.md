# v1.8.1 post-release platform evidence — 2026-08-21

## Outcome

The remaining v1.8.1 platform evidence is complete. The public v1.8.0 build
performed normal in-app updater handoffs to v1.8.1 on macOS and Windows, and
the published v1.8.1 Linux AppImage passed authenticated download and launch
verification. No release gate was waived.

## macOS v1.8.0 to v1.8.1 updater handoff

The public signed and notarized v1.8.0 Apple Silicon ZIP was extracted to an
isolated temporary path so the installed Blanc profile and application were
not modified during the check:

1. The v1.8.0 ZIP SHA-256 matched the public release checksum, strict deep
   code-sign verification passed, and Gatekeeper reported `Notarized
   Developer ID`.
2. Packaged v1.8.0 discovered the public v1.8.1 update, reused the exact public
   ZIP already held in Blanc's updater cache, verified it, and handed it to
   Squirrel.Mac after **Restart Now** was selected.
3. ShipIt recorded the install request, moved the old bundle aside, installed
   the update into the same temporary application path, reported
   `Installation completed successfully`, and relaunched Blanc.
4. The resulting bundle reported v1.8.1, launched independently with the
   isolated profile, and passed strict deep code-sign verification.

This was the real Squirrel/ShipIt updater path initiated inside packaged
v1.8.0, not a direct v1.8.1 ZIP or DMG launch.

## Windows v1.8.0 to v1.8.1 updater handoff

The normal public updater path completed in a Windows 11 Parallels VM:

1. The public v1.8.0 NSIS installer had SHA-256
   `424f0af7125e0d6bd7f5c10111ac09ec800fa0b90fc67b98cb56e5002eaaee19`.
   Windows Authenticode validation reported `Valid`, the expected Bananify
   Creative publisher, and a Microsoft timestamp authority.
2. Packaged v1.8.0 discovered v1.8.1, downloaded the complete 101.2 MB
   installer, reached 100%, and showed **Update 1.8.1 downloaded**.
3. Selecting **Restart Now** produced `Install on explicit quitAndInstall` in
   the updater log and invoked the pending v1.8.1 NSIS installer with the
   updater handoff arguments.
4. The old process exited, NSIS completed, and Blanc relaunched. The installed
   executable reported file version `1.8.1.0`; the visible start-page footer
   reported `v1.8.1`.

On this VM, PowerShell Authenticode inspection exceeded Blanc's 120-second
infrastructure timeout, so the updater used its designed SHA-512 feed-integrity
fallback. The same downloaded installer was independently Authenticode-valid;
the timeout was not treated as signature evidence.

This was an updater handoff begun inside v1.8.0. It was not a directly launched
NSIS installer.

## Linux v1.8.1 AppImage

GitHub Actions run `32496506720` downloaded the public
`Blanc-1.8.1.AppImage` and `SHA256SUMS`, matched the artifact to the release
manifest, and verified its GitHub provenance attestation. It then launched the
actual AppImage under Xvfb with an isolated profile and observed all of the
following over Chromium's debugging endpoint:

- `blanc-chrome://index/`
- `blanc-chrome://overlay/`
- `blanc://newtab/`
- the rendered version marker `v1.8.1`

The reusable check lives in `scripts/smoke-public-appimage.mjs` and the
`published-linux-appimage` job in `.github/workflows/prerelease-smoke.yml`.
It verifies the published artifact rather than an unpacked build directory.
