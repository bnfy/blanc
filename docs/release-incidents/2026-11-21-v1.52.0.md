# Blanc v1.52.0 release — November 21, 2026

Status: published and independently verified at 19:43 UTC on November 21,
2026 (14:43 EST), from `a0506da144b6be952fe49f241e54dd2063d333a3`. The press
gate ran six times before `release.sh` could start, because five merges to
`main` landed during gate runs (below); the release itself ran end to end in
one attempt and exited 0. The press gate ran on the owner's Mac Studio; three
acceptance scenarios that the Studio's environment fails passed on the
release Mac with the owner's approval. Updater handoffs from v1.51.0 are
pending.

## Scope

The 1.52 feature release, on the same runtime as v1.51.0, castLabs' Electron
for Content Security `45.2.1+wvcus`. Checked on November 21, 2026, before
signing, castLabs' newest stable release was still `v45.2.1+wvcus`; the only
newer one was the `v46.0.0-alpha.7+wvcus` pre-release.

Release notes: [v1.52.0](../press/release-notes/v1.52.0.md), prepared in #1674
(merged as `f14e543b4`).

- **Added:** Spaces across profiles (#1642, #1658); opening local HTML files
  on Windows (#1634).
- **Fixed:** pop-up windows that ask before closing (#1632); no passkey
  prompt on page load on Windows (#1637); a local HTML file Blanc can't show
  says why (#1659); the auto-hidden Island shows when a download starts
  (#1673); the Start Page wallpaper always finishes fading in (#1669).

Not hand-checked before release (listed in `unreleased.md`): the download
peek in a packaged build, opening an HTML file from Explorer in an installed
build, the Windows passkey fix with Windows Hello and on real sites, the
refused-file message in a packaged build, and a real Proxmox console window.

## Press gate

Run with `npm run release:prepare` on the Mac Studio in a detached worktree,
with the release Mac's Node 22.23.4 and npm 11.4.2 and its
`BLANC_1P_ACCOUNT` passed over stdin. Before each run both machines computed
the same gate key, and the Studio's ledger was copied into the release
worktree, where `release:prepare` ran the scenarios the Studio failed.

Five merges to `main` voided a completed or running gate, each by moving
`origin/main` past the gated commit:

| Gated commit | Voided by | What it changed |
|---|---|---|
| `59d7f26` | #1676 (`8407a6d`) | the Android fork build fix |
| `8407a6d` | #1678 (`1454a50`) | the Windows beta `.903` Download page |
| `1454a50` | #1671, #1679, #1680 (`61c1e91`) | docs, Android A6, shared strings; merged by auto-merge armed before the hold |
| `61c1e91` | #1460 (`015d615`) | the Spaces site copy; its auto-merge was re-armed three times after it was turned off |
| `b1155d5` (after #1683, which the owner chose to merge first) | #1685, #1686 (`a0506da`) | the Windows beta `.904` Download page and docs, merged after the owner told that session the release had started |

The sessions working in this repository were asked to hold merges until
`release.sh` passed its `HEAD == origin/main` check, and were told when it
had.

At `a0506da` the Studio run passed every stage except 3 of 640 acceptance
scenarios, which failed on the first run and again on the fresh rerun:
`quiet-tabs.feature:77` and `tabs-and-groups.feature:367`, as for v1.50.0 and
v1.51.0, and `island-and-commands.feature:87`, the third Studio-only failure
from v1.50.0. The owner approved running the Studio's failures on the release
Mac (MacBook Pro, Retina), where `release:prepare` passed all three.
