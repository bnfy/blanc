# Blanc v1.50.0 release — November 18, 2026

Status: published and independently verified at 01:49 UTC on November 18,
2026 (20:49 EST on November 17), from
`3edf12275765ec1759b7de987247e9743aba6b56`. `release.sh` ran end to end in one
attempt and exited 0. The press gate ran on the owner's Mac Studio; three
acceptance scenarios that the Studio's environment now fails (the published
v1.49.1 fails them there too) passed on the release Mac with the owner's
approval. The macOS and Windows updater handoffs from v1.49.1 are pending.

## Scope

The 1.50 feature release, on the same runtime as v1.49.1, castLabs' Electron
for Content Security `45.2.1+wvcus`. Checked on November 17, 2026, castLabs'
newest stable release was still `v45.2.1+wvcus`; the only newer one was the
`v46.0.0-alpha.7+wvcus` pre-release.

Release notes: [v1.50.0](../press/release-notes/v1.50.0.md), prepared in #1605
(merged as `a73bd896c`). The prep review fixed two lines: the Site permissions
path (Settings → Privacy) and the Okta line, which now says it hasn't been
tried with a real Okta Verify.

- **Added:** the Favorites manager with folders inside folders, one **Bring
  my stuff to Blanc** dialog, the nested Favorites menu and `/save` paths
  (F63, #1590, #1592); a per-site prompt before a website reaches this device
  or the local network (#1593).
- **Changed:** downloads save to the Downloads folder without asking, one per
  real click, with **Ask where to save each file** to bring Save As back
  (#1596, #1598).
- **Fixed:** websites that check the local-network permission first get
  Blanc's prompt instead of a refusal (#1585, Okta Verify FastPass).

Not hand-checked before release (listed in `unreleased.md`): Favorites drag
and drop with a real mouse, the nested Favorites menu in a packaged build, the
first-time macOS Downloads prompt, and a real enrolled Okta Verify.

## Press gate

Run with `npm run release:prepare` on the Mac Studio in a detached worktree at
`3edf12275`, with the release Mac's Node 22.23.4 and npm 11.4.2 installed
privately there and the release Mac's `BLANC_1P_ACCOUNT` passed over stdin.
Both machines computed gate key `3ab6b0ac7572…`, and the Studio's ledger was
copied into the release worktree.

The Studio run passed every stage except 3 of 623 acceptance scenarios, which
failed on the first run and again on the fresh rerun:

- `island-and-commands.feature:87` (hover-open with vertical tabs): the
  Island never reported the pointer inside.
- `quiet-tabs.feature:77` (quiet rows dim at rest): the panel row's opacity
  stayed 1.
- `tabs-and-groups.feature:367` (a bigger Island): the pill measured 1px
  taller than expected at every size.

A control on the Studio the same evening ran the same three at the published
v1.49.1 tag, and they failed the same way; they had passed in v1.49.1's own
gate on that Studio on November 15. So the Studio's environment changed, not
Blanc. Confirmed: the Studio's display now runs at 1x (1920×1080) and the
console belongs to the owner's account. Plausible, unproven: the 1x display
causes all three. The owner approved running the three on the release Mac
(MacBook Pro, Retina), where `release:prepare` passed them in 9.5 s.
