# Blanc v1.36.0 release — October 17, 2026

Status: published and independently verified; public v1.36.0 is the baseline.
The adjacent public-feed updater handoffs (v1.35.0 → v1.36.0) on macOS and
Windows, the blanc.day deploy with the Bangs page, and the Windows and Linux
hand checks listed below are pending.

## Scope

A minor release with these app changes merged since v1.35.0.

- **Bangs (F47, #876).** A known `!code` at the start or the end of the text
  in the ⌘L panel puts a hint row at the top of the list and opens that
  site's search directly, for every search engine; a bare code opens the
  site. `!` alone lists recently used and popular bangs, and more letters
  filter Kagi's bundled MIT bang list (10,624 bangs, pinned like the
  blocklists). Settings → General has a Bangs switch and Your bangs. No
  suggestion request is made for bang-shaped text.
- **Island lower section, four PRs** from
  `docs/superpowers/specs/2026-10-16-island-lower-section-design.md`:
  - **#874:** Recently closed becomes a band under Pinned that starts folded,
    lists up to 25 entries and can be dragged among the groups; its place is
    kept per window and in each space.
  - **#875:** a one-line footer (New tab, Private, Other devices, tools), the
    Other devices drawer, a Glance icon on the row, sentence case across the
    panel, and slash commands and bang codes in small chips.
  - **#877:** group names keep their case (with a one-time capital for names
    saved in lowercase), and a group header menu with Rename Group…, Ungroup
    and Close Group.
  - **#878:** Rename Device… in the drawer and This device's name in
    Settings → Sync, synced as the new `deviceNames` settings key.
- **Sync pairing (#866).** Add another device shows an eight-character code
  good for ten minutes; Add this device to my sync enters it; Connect to a
  different sync with a code; Copy recovery code. The Worker's pairing route
  was already live before launch: `GET /v1/pair/<64 hex>` answered
  `{"error":"not-found"}` (a JSON 404).
- **Tab sync (#859).** A tab whose title changes more often than every 15 s
  no longer postpones the open-tab publish forever, and a Mac publishes its
  computer name instead of a network-derived host name.
- **Invite a Friend (#880).** Help → Invite a Friend… and `/invite` open a
  prefilled email in the default mail app, falling back to the clipboard.
- **What's new (#886).** After an update, the Start Page footer shows a
  What's new pill linking to the release on the changelog for seven days.
- **Default browser (#882).** Finish setup leads with Make Blanc your default
  on macOS and Windows, and new installs get one reminder 12 hours to 14 days
  after setup.
- **About (#872)** shows the Chromium version. **Blanc.exe (#855)** names
  Bananify Creative as its company, so Windows Firewall and Settings → Apps
  show that publisher.

Release notes: [v1.36.0](../press/release-notes/v1.36.0.md) (prep #887, plus

## Attempt 1: stopped before the tag

Launched in Terminal.app from `d693b3cd` (#887) at about 11:24 UTC. The press
gate, both notarized builds and every packaged check through the second
favicon matrix passed. The packaged migration check from public v1.35.0 then
failed:

> AssertionError: candidate should preserve the saved tab group

The check's fixture saves a group named `research` and looked it up by that
exact name. Since #877 a candidate gives an all-lowercase saved name a capital
once, so 1.36.0 restores it as **Research**, the intended behavior. The check
runs only inside `release.sh`, so #877's CI never ran it. Against the same
signed build, a diagnostic run that found the group ignoring case printed
`["research"]` for 1.35.0 and `["Research"]` for the candidate's first launch,
restart and future-format startup, and every other migration assertion
passed. No tag, draft or release existed, so the version was not burned.

**#889** made the check find the group ignoring case and require every
candidate launch to show "Research", leaving the public baseline's spelling
unpinned. It passed on the same signed build, and a control with 1.35.0 as the
candidate failed on the new assertion. A resume wasn't possible because the
build stamp names the source commit.

Before relaunching, the commits since `d693b3cd` were listed. #882 and #886 had
merged after the prep and would ship, so the owner chose to keep them and add
notes (#890).
