# Blanc v1.36.0 release — October 17, 2026

Status: published and independently verified; public v1.36.0 is the baseline.
The owner confirmed both adjacent public-feed updater handoffs (v1.35.0 →
v1.36.0), on macOS and on Windows, and blanc.day is deployed with the Bangs
page. The Windows and Linux hand checks ran on October 17. One found a Linux
bug: with no mail app, Invite a Friend does nothing (see below).

## Scope

A minor release with these app changes merged since v1.35.0.

- **Bangs (F47, #876).** A known `!code` at the start or the end of the text
  in the ⌘L panel puts a hint row at the top of the list and opens that
  site's search directly, for every search engine; a bare code opens the
  site. `!` alone lists recently used and popular bangs, and more letters
  filter Kagi's bundled MIT bang list (10,624 bangs, pinned like the
  blocklists). Settings → General has a Bangs switch and Your bangs. No
  suggestion request is made for bang-shaped text.
- **Island lower section, four PRs** from
  `docs/superpowers/specs/2026-10-16-island-lower-section-design.md`:
  - **#874:** Recently closed becomes a band under Pinned that starts folded,
    lists up to 25 entries and can be dragged among the groups; its place is
    kept per window and in each space.
  - **#875:** a one-line footer (New tab, Private, Other devices, tools), the
    Other devices drawer, a Glance icon on the row, sentence case across the
    panel, and slash commands and bang codes in small chips.
  - **#877:** group names keep their case (with a one-time capital for names
    saved in lowercase), and a group header menu with Rename Group…, Ungroup
    and Close Group.
  - **#878:** Rename Device… in the drawer and This device's name in
    Settings → Sync, synced as the new `deviceNames` settings key.
- **Sync pairing (#866).** Add another device shows an eight-character code
  good for ten minutes; Add this device to my sync enters it; Connect to a
  different sync with a code; Copy recovery code. The Worker's pairing route
  was already live before launch: `GET /v1/pair/<64 hex>` answered
  `{"error":"not-found"}` (a JSON 404).
- **Tab sync (#859).** A tab whose title changes more often than every 15 s
  no longer postpones the open-tab publish forever, and a Mac publishes its
  computer name instead of a network-derived host name.
- **Invite a Friend (#880).** Help → Invite a Friend… and `/invite` open a
  prefilled email in the default mail app, falling back to the clipboard.
- **What's new (#886).** After an update, the Start Page footer shows a
  What's new pill linking to the release on the changelog for seven days.
- **Default browser (#882).** Finish setup leads with Make Blanc your default
  on macOS and Windows, and new installs get one reminder 12 hours to 14 days
  after setup.
- **About (#872)** shows the Chromium version. **Blanc.exe (#855)** names
  Bananify Creative as its company, so Windows Firewall and Settings → Apps
  show that publisher.

Release notes: [v1.36.0](../press/release-notes/v1.36.0.md) (prep #887, plus
#890 for #882 and #886, which merged after the prep). Stable mode, platforms
`mac,windows,linux`, `BLANC_MAC_ARCHES=arm64,x64`, from
`3c214274958c15d8f3b28f8c61f2fac26937e333`. Electron stays 44.8.0 (Chromium

#865, #869, #881, #883, #884, #888, #889) change no app behavior.

## Attempt 1: stopped before the tag

Launched in Terminal.app from `d693b3cd` (#887) at about 11:24 UTC. The press
gate, both notarized builds and every packaged check through the second
favicon matrix passed. The packaged migration check from public v1.35.0 then
failed:

> AssertionError: candidate should preserve the saved tab group

The check's fixture saves a group named `research` and looked it up by that
exact name. Since #877 a candidate gives an all-lowercase saved name a capital
once, so 1.36.0 restores it as **Research**, the intended behavior. The check
runs only inside `release.sh`, so #877's CI never ran it. Against the same
signed build, a diagnostic run that found the group ignoring case printed
`["research"]` for 1.35.0 and `["Research"]` for the candidate's first launch,
restart and future-format startup, and every other migration assertion
passed. No tag, draft or release existed, so the version was not burned.

**#889** made the check find the group ignoring case and require every
candidate launch to show "Research", leaving the public baseline's spelling
unpinned. It passed on the same signed build, and a control with 1.35.0 as the
candidate failed on the new assertion. A resume wasn't possible because the
build stamp names the source commit.

Before relaunching, the commits since `d693b3cd` were listed. #882 and #886 had
merged after the prep and would ship, so the owner chose to keep them and add
notes (#890).

public 1.36.0 x64 build):

Results:

- **About Blanc (#872) passes.** Alt+F opens the main menu; Help → About
  Blanc shows "Blanc / 1.36.0 / © 2026 Bananify / Independent browser by
  Bananify. / Chromium 152.0.7977.167"
  ([capture](../evidence/2026-10-17-v1.36.0-hand-checks/windows-about.png)).
- **Publisher (#855) passes.**
  - `Blanc.exe`'s version info reads CompanyName "Bananify Creative" and
    LegalCopyright "Copyright © 2026 Bananify Creative".
  - Its Authenticode signature is Valid and timestamped, with subject
    `CN=Bananify Creative, O=Bananify Creative, L=North Chili, S=New York,
    C=US`.
  - The uninstall entry Settings → Apps reads is "Blanc 1.36.0", publisher
    "Bananify Creative".
  - The firewall prompt itself wasn't raised. The installed path already has
    its Allow rules, and raising one for a copy would mean answering a
    firewall prompt, which is a security setting. The prompt's publisher
    comes from the same version info.
- **Invite a Friend (#880): handed off.** Help → Invite a Friend… passed the
  `mailto:` link to Windows. The VM's registered mail app isn't installed, so
  Windows showed "Select an app to open this 'mailto' link" (Outlook, Mail,
  Mimestream and others). It wasn't silent, and nothing was chosen.
- **Default browser (#882): passes.**
  - Finish setup leads with "Make Blanc your default", shown Completed,
    because Blanc is this VM's default (`BlancURL` for http and https).
  - Settings therefore shows "Blanc is your default browser" and hides its
    button. The handoff was called through the Settings page's own bridge
    (`bowserPages.defaultBrowser.set`, the request the button, the checklist
    item and the reminder share). It opened Settings → Apps → Default apps.
  - Nothing was chosen; https was still `BlancURL` afterwards, and the
    Settings window was closed.
  - The one-time reminder dialog wasn't shown. It needs a machine where Blanc
    isn't the default, and both test machines have Blanc as the default.

**Linux** (the "Ubuntu 26.04 ARM64" Parallels VM, GNOME Wayland). The public
Linux release is x64 only, so the checks ran on an exact-tag ARM64 build:
`v1.36.0` = `3c214274`, Electron 44.8.0, Chromium 152.0.7977.167, built in the
VM. Its `chrome-sandbox` was made setuid root, as Chromium packages install
it. `prlctl` key events and `xdotool` didn't reach Blanc's own menu on this
VM, and `prlctl capture` returned stale frames. So a main-process driver
(`electron -r`) on the tag checkout clicked the real Help menu items, which
are the same click handlers a person triggers.

- **About Blanc (#872) passes.** GTK's About dialog shows "Blanc / 1.36.0 /
  Chromium 152.0.7977.167", then the Website link and "© 2026 Bananify"
  ([capture](../evidence/2026-10-17-v1.36.0-hand-checks/linux-about.png),
  taken under XWayland by window id).
- **Invite a Friend (#880): fails when no mail app is set up.**
  - The VM has no `x-scheme-handler/mailto` handler. `xdg-open` received the
    full prefilled `mailto:` link and failed (`gio: … The specified location
    is not supported`).
  - A standalone probe on the same Electron 44.8.0 shows
    `shell.openExternal('mailto:…')` resolving anyway, after 506 ms. So
    `invite-friend.js` reports `'mail'` and never copies the invite.
  - Help → Invite a Friend… and `/invite` (typed into the ⌘L panel, whose row
    shows the new chip) both did nothing visible and copied nothing.
  - A Linux machine with a mail client set up should open the compose
    window; that wasn't tried here.
  - Separately, the Help menu path shows no notice even when the fallback
    does copy; only `/invite` does.
  - The release notes' "If no mail app opens, the invite is copied" holds on
    macOS (not tried) and Windows (where Windows asks which app to use), but
    not on Linux. `docs/marketing-claims.md` now says so.
- Side finding: on this Electron, `clipboard.readText()` returns a promise.
  Blanc's own readers (`address-menu.js`) already await it.
