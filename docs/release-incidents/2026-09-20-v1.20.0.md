# v1.20.0 standalone Mahjong and app handoff release — 2026-09-20

Status: public and independently verified; canonical site deployment and
adjacent updater handoffs remain pending. Published at

Release: <https://github.com/bnfy/blanc/releases/tag/v1.20.0>.

## Scope

- Mahjong launches in a managed tab from the footer of Ledger, Billboard,
  Shelf, or Tally. Direct `blanc://mahjong/` links remain valid. A stored
  Mahjong start-page layout migrates to Billboard without changing other
  layouts or deleting unfinished games. Standalone gameplay, scoring,
  Records, and save formats are unchanged.
- Mahjong's header uses the Sunrise mark and the game retains its green
  lacquer board, tile illustrations, and separate purple private treatment.
  The white-dragon B remains an intentional historical tile detail. No site
  screenshot was altered to suggest this shipped before publication.
- Consented external-app login callbacks discover OS-registered handlers
  rather than relying on a service list. Browser/system-control schemes
  remain blocked; a page can prompt at most once per native activation.
- The macOS bundle build number advances to 1200. Electron remains at
  44.4.3, the latest stable version checked during preparation.

## Preparation and manual-test decision

- Release-prep PR <https://github.com/bnfy/blanc/pull/401> squash-merged after
  all seven protected checks passed. Local lint, substrate, unit tests,
  163 desktop scenarios / 980 steps, standalone Mahjong smoke, cold launch,
  Web Store guard, OAuth, DNS, dependency audit, and 26-page site/SEO build
  passed. The release operator repeated the complete press gate from the
  merged source.
- Private signed Windows/Linux validation
  <https://github.com/bnfy/blanc/actions/runs/35526128232> passed both
  platform jobs, including packaged payload, fuse, Authenticode, and Linux
  AppImage checks. This is package evidence, not a real account-login check.
- The owner confirmed real installed-app sign-in on macOS. When explicitly
  asked whether to test Windows/Linux sign-in before release or waive those
  two checks despite possible OS protocol differences, the owner replied
  “waive.” The decision and scope were preserved on
  <https://github.com/bnfy/blanc/pull/401#issuecomment-5751485988>.
  **Windows and Linux real installed-app sign-in were not performed.** Their
  native protocol handlers or login callbacks could behave differently from
  macOS despite green automated and package checks. This risk remains open;
  neither manual check is represented as passing.
