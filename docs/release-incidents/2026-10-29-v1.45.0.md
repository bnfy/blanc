# Blanc v1.45.0 release — October 29, 2026

Status: published and independently verified at 03:55 UTC on October 29, 2026
(the evening of October 28 in the owner's time zone), from tag `v1.45.0` =
`6f1bc523d2f0d432d5c4119b9f7ec22a324dbd2d`, on the fourth attempt. Every
earlier attempt stopped before a tag existed. The owner confirmed the macOS
and Windows updater handoffs from v1.44.1 on October 29, 2026.

## Scope

The same castLabs Electron for Content Security pin as v1.43.x and v1.44.1
(`44.9.3+wvcus`, Chromium 152.0.7977.167), so Widevine playback, uBO's
reviewed runtime record and the owner's runtime waivers in
[the ECS runtime security review](../ecs-runtime-security-review-2026-10-23.md)
carry over unchanged. Release notes: [v1.45.0](../press/release-notes/v1.45.0.md).

- **Added:** Shared Spaces; Recently closed on every device (for shared
  Spaces); Turn on Sync without a passphrase; Connect your iPhone; Play the
  Sunrise when Blanc opens; links opened in a new tab can follow link rules.
- **Changed:** vertical tabs show the current Space's mark and a new-group
  button.
- **Fixed:** a tab a site opened in the background no longer blocks switching
  Spaces once it has loaded (#1217); site icons that aren't square keep their
  shape (#1245).

The What's New page for 1.45 (`https://blanc.day/whats-new/1.45`) was live
before the release (below).

## The attempts

1. **Attempt 1** stopped in the press gate on `@F27-15` and `@F27-16`
   ("timed out waiting for no protected window"). Nothing was built or tagged.
2. **Attempt 2** stopped at the same two scenarios.

   Root cause: on macOS 27.2, Electron 44's `isContentProtected()` keeps
   reporting `true` after `setContentProtection(false)` when Blanc is launched
   from Terminal or LaunchServices, although the window captures normally.
   A minimal probe app and a real screen capture both proved it. The product
   was fine; the test hook read the wrong signal. #1256 makes the test hook
   report the window Blanc protected rather than `isContentProtected()`.
3. **Attempt 3**, from `6f1bc523d` (#1256 merged), passed the whole press
   gate, built both Mac architectures, VMP-signed, Developer ID signed and
   notarized them, and passed the packaged checks. It then stopped at
   `test:packaged:migration`.

   Root cause: 1.45.0 is the first feature release whose What's New page was
   live before the migration step, so the update from v1.44.1 opened the
   What's New 1.45 tab, which joined the smoke's saved Space, and the smoke
   didn't expect an extra tab. The product behaved as designed. #1257 fixes
   the test (it accepts that tab); run by hand against attempt 3's signed
   build, the old assertion fails and the new one passes. #1257 merged after
   the tag and isn't in the release.
4. **Attempt 4** resumed attempt 3's verified build with
   `BLANC_RELEASE_RESUME_FROM=ecs-acceptance` (stamp commit `6f1bc523d`),
   which skips `test:packaged:migration`.

   **Owner waiver (in chat, October 28, 2026):** skip the migration step for
   this release on the evidence of that manual run of the fixed smoke against
   the same signed build. Risk: the migration smoke didn't pass inside
   `release.sh` for 1.45.0; the evidence is the manual run. The next release
   runs it in the gate with #1257 and migrates from v1.45.0.

   Attempt 4 then created the tag and draft, dispatched the native run,
   built the complete manifest, completed the Sigstore authorization and
   published.

## Shared Spaces: the owner's decision and Gate D

The owner decided to ship Shared Spaces in 1.45.0 once Gate D passed
(`isSharedSpacesOffered()` turns on from 1.45). The record is
[Shared Spaces Gate D](../reviews/2026-10-28-shared-spaces-gate-d-1.45.0.md).

- **First run: FAIL** (#1249). Quitting Blanc while a Shared Space window
  held back a change from another device made that device delete tabs nobody
  closed, and the deletion reached every device (B1). Linux wasn't run.
- **Fixes:** #1251 (quitting while a change is held no longer deletes tabs,
  B1) and #1254 (a group made after sharing keeps its tabs).
- **Rerun: PASS** on every check run, Mac↔Windows and Mac↔Linux (#1255), on
  the #1254 head `ab9d568f4`. Linux ran the AppImage's extracted payload,
  because the VM's AppArmor setting
  (`kernel.apparmor_restrict_unprivileged_userns=1`) blocks AppImages; the
  `app.asar` was identical. Not covered: local `file://` tabs, the rail's New
  group on Windows and Linux, Intel Mac, x64 Linux, Linux on X11, and
  notarized builds.
- **Owner platform confirmations:** the owner gave written confirmations for
  Mac, Windows and Linux in chat on October 28, 2026.
