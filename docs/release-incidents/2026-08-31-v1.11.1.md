# v1.11.1 microphone-permission hotfix — 2026-08-31

Status: published; macOS adjacent updater handoff passed; Windows adjacent
updater handoff pending.

Blanc v1.11.1 is an emergency macOS media-permission correction based on the
public v1.11.0 source. It was published from immutable source commit
`a3b079ab0b04088b5518c0008808abff09a54ab1` at `2026-09-01T01:51:06Z`:
<https://github.com/bnfy/blanc/releases/tag/v1.11.1>.

## User-visible failure

On public v1.11.0, a website such as ChatGPT could receive an `allow` decision
from Blanc and Blanc's capture indicator could turn on while the site still
received no live microphone input. macOS Privacy & Security did not list Blanc
as an application that had requested microphone access.

## Root cause and escaped test gap

Blanc implemented its own per-site media decision but never bridged an allowed
decision to macOS Transparency, Consent, and Control (TCC) with Electron's
native `systemPreferences.askForMediaAccess` API. Its signed hardened-runtime
entitlements also omitted Apple's audio-input and camera capabilities. The
capture indicator observed the site grant, which occurs before Chromium
establishes a native stream, so it could appear active despite both missing
native requirements.

The initial manual microphone check was run through `npm start`. That exercises
the development Electron identity, which already had microphone access on the
test Mac, rather than the signed Blanc identity. The later packaged regression
used Electron's `--use-fake-device-for-media-stream` flag for determinism. It
proved Blanc's site prompt, live `PermissionStatus`, and capture plumbing, but
it bypassed the native-device/TCC boundary. Both checks therefore passed without
proving that signed Blanc itself requested and received macOS microphone access.

## Correction

- macOS media grants now query and, when needed, request the matching native
  microphone or camera access before Blanc authorizes capture.
- The signed main app and ordinary Chromium helpers now carry Apple's narrow
  hardened-runtime audio-input and camera entitlements; site and TCC decisions
  still gate every use.
- Stored site-level allows from older Blanc versions still pass through the
  native gate, so existing users receive the missing macOS request without
  another Blanc site prompt.
- Native denial fails closed while preserving the site decision. If the user
  later enables Blanc in System Settings and restarts it, the approved site can
  request media again without a duplicate site prompt.
- Blanc's capture observer now runs only after both the site decision and the
  native decision permit capture.
- The macOS package now declares both microphone and camera usage descriptions.
