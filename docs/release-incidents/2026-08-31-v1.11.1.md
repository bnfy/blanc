# v1.11.1 microphone-permission hotfix — 2026-08-31

Status: candidate verified; publication evidence pending.

Blanc v1.11.1 is an emergency macOS media-permission correction based on the
public v1.11.0 source. The immutable source commit, release link, workflow, and
publication timestamp will be recorded here after the release completes.

## User-visible failure

On public v1.11.0, a website such as ChatGPT could receive an `allow` decision
from Blanc and Blanc's capture indicator could turn on while the site still
received no live microphone input. macOS Privacy & Security did not list Blanc
as an application that had requested microphone access.

## Root cause and escaped test gap

Blanc implemented its own per-site media decision but never bridged an allowed
decision to macOS Transparency, Consent, and Control (TCC) with Electron's
native `systemPreferences.askForMediaAccess` API. Its signed hardened-runtime
entitlements also omitted Apple's audio-input and camera capabilities. The
capture indicator observed the site grant, which occurs before Chromium
establishes a native stream, so it could appear active despite both missing
native requirements.

The initial manual microphone check was run through `npm start`. That exercises
the development Electron identity, which already had microphone access on the
test Mac, rather than the signed Blanc identity. The later packaged regression
used Electron's `--use-fake-device-for-media-stream` flag for determinism. It
proved Blanc's site prompt, live `PermissionStatus`, and capture plumbing, but
it bypassed the native-device/TCC boundary. Both checks therefore passed without
proving that signed Blanc itself requested and received macOS microphone access.

## Correction

- macOS media grants now query and, when needed, request the matching native
  microphone or camera access before Blanc authorizes capture.
- The signed main app and ordinary Chromium helpers now carry Apple's narrow
  hardened-runtime audio-input and camera entitlements; site and TCC decisions
  still gate every use.
- Stored site-level allows from older Blanc versions still pass through the
  native gate, so existing users receive the missing macOS request without
  another Blanc site prompt.
- Native denial fails closed while preserving the site decision. If the user
  later enables Blanc in System Settings and restarts it, the approved site can
  request media again without a duplicate site prompt.
- Blanc's capture observer now runs only after both the site decision and the
  native decision permit capture.
- The macOS package now declares both microphone and camera usage descriptions.

## Pre-publication evidence

- Native-gate unit coverage verifies granted, denied, restricted,
  not-determined, error, concurrent, microphone, and camera paths.
- Permission-policy coverage verifies fresh grants, older stored grants, live
  `PermissionStatus` changes, native denial, retry after a System Settings
  change, and the capture-observer ordering boundary.
- Packaging coverage verifies the two required usage descriptions and native
  gate wiring across Personal, private, and named-profile sessions.
- The complete unit suite and all 127 live desktop acceptance scenarios / 781
  steps passed on the candidate source.
- The corrected signed, unpacked 1.11.1 arm64 candidate passed strict deep
  Developer ID signature, provisioning-profile/WebAuthn, packaged payload,
  deterministic release-regression, and signed-entitlement gates. The latter
  inspects DER ground truth on the main app and ordinary Chromium helpers for
  both audio-input and camera capabilities.
- The initial real-device harness launched the app executable directly. It
  received a live track through the automation host's existing access, so that
  run is explicitly not counted as first-request TCC evidence. A corrected
  LaunchServices run against the exact signed bundle then exposed the missing
  hardened-runtime entitlement by closing at native access.
- After every Blanc process was closed and the app-specific TCC decision was
  reset, the corrected harness opened the exact rebuilt `.app` through macOS
  LaunchServices. The request completed, macOS Privacy & Security listed
  **Blanc** with Microphone access on, and the candidate measured a live
  microphone peak of `0.063`. No audio was recorded or persisted.
- The user then exercised the original failing surface end to end in that exact
  signed candidate: **ChatGPT → Start Voice → Turn on microphone**. Blanc's
  chrome reported `microphone in use`, ChatGPT transcribed “Hello, can you hear
  me” and “Just testing to see if this works with Blanc browser now,” and
  answered that the audio was coming through clearly. Ending Voice removed the
  capture indicator and rendered the complete transcript. This is the
  release-blocking product smoke; the generic media harness is supporting
  coverage rather than a substitute for the ChatGPT Voice flow.
- Windows and Linux now run a local-only packaged microphone gate in their
  native build jobs. It checks Blanc's site prompt, retained `PermissionStatus`
  transition, canonical status object, granted stream, and live audio track in
  the Windows unpacked signed binary and the final Linux AppImage. Private run
  33456559428 passed the Windows gate plus exact publisher/timestamp
  Authenticode validation. Its first Linux attempt never reached Blanc: the
  unpacked CI directory's `chrome-sandbox` intentionally lacked the root/4755
  ownership that the production AppImage mount supplies. The gate was corrected
  to launch the actual AppImage. Linux-only run 33456792890 then stopped before
  Blanc launched because the builder image lacks FUSE 2. The workflow now
  installs the same `libfuse2`/Xvfb runtime already used by Blanc's authenticated
  public AppImage smoke. Linux-only run
  <https://github.com/bnfy/blanc/actions/runs/33456902794> then passed the final
  AppImage microphone/live-track gate, packaged blocker and compliance checks,
  hardened fuse check, and private-artifact upload.
- Combined private validation run
  <https://github.com/bnfy/blanc/actions/runs/33456559428> passed the Windows
  packaged microphone/live-track gate, packaged blocker/compliance and hardened
  fuse checks, exact publisher/timestamp Authenticode verification, and private
  signed-artifact upload. Its Linux failure was the pre-launch unpacked-sandbox
  harness issue documented above; the succeeding AppImage run supersedes that
  Linux-only result.
