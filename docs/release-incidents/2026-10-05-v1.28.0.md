# Blanc v1.28.0 release — October 5, 2026

Status: published and independently verified; public v1.28.0 is the baseline.
The adjacent public-feed macOS handoff (v1.27.0 → v1.28.0) is owner-confirmed.
The Windows public-feed update installed, but only on a leftover test copy, so
the Windows handoff is not confirmed for a normal install; see below.

Scope: Dark websites, Match site colors, resumable and retryable downloads,
continuing past certificate warnings on local addresses, the start-page layout
polish, three uBlock Origin host fixes (#534, #567, #568), the utility-sheet
load deadline and the Island footer overflow fix. Release notes:
[v1.28.0](../press/release-notes/v1.28.0.md). Stable mode, platforms
`mac,windows,linux`, `BLANC_MAC_ARCHES=arm64`, from `ec98a138` (PR #574).

## Duplicate macOS build number

Version 1.28.0 shipped with macOS bundle build **1274**, the same build as
v1.27.0. The release-prep PR bumped `version` but not
`build.mac.bundleVersion`, and no gate compares the build with the previous
public release. Updates are unaffected: Squirrel.Mac and electron-updater
compare the version string, and the staged 1.27.0 → 1.28.0 update below
passed. The visible effect is that About reads "1.28.0 (1274)". Released
assets are immutable, so the next release must move `bundleVersion` above
1274.

## Adjacent public updater handoffs

**macOS: confirmed.** On October 5, 2026 the owner reported **“Mac updated.”**
The owner's `updater.log` shows public v1.27.0 finding 1.28.0 on the public
feed at `01:20:03Z`, downloading `Blanc-1.28.0-arm64-mac.zip` in full, and
Squirrel.Mac receiving it (`update-downloaded`) at `01:20:08Z`. At `01:20:15Z`
the running app reported 1.28.0 as current. `/Applications/Blanc.app` reports
1.28.0. The seven-second gap between staging and the relaunched 1.28.0 is
consistent with **Restart Now**; the log does not name the button.

**Windows: update installed, not confirmed on a normal install.** On
October 5 the owner ran the public update on the Windows 11 VM. Its
`updater.log` shows public 1.27.0 finding and downloading 1.28.0, then
`quitAndInstall` launching `Blanc-Setup-1.28.0.exe --updated /S --force-run`
at `01:49:45Z` and the app quitting at `01:49:52Z`. 1.28.0 was installed, but
Blanc did not reopen by itself, and the owner's taskbar pin to Blanc
disappeared; the owner relaunched 1.28.0 from the Start menu at `01:51:25Z`.

That installation was not a normal install. Blanc was running from
`%LOCALAPPDATA%\BlancUboUpdate1272\Installed`, a leftover copy from the
v1.27.0 candidate (build 1272) validation, and the standard
`%LOCALAPPDATA%\Programs\blanc` did not exist; the owner confirmed it was
still a local test copy. Windows packaging (`build/installer.nsh`, the
electron-builder configuration, app ID and install location) is identical
between v1.27.0 and v1.28.0, so the evidence points to the non-standard test
install rather than a 1.28.0 regression. NSIS writes no installer log, so the
exact cause of the missed relaunch and the lost pin is not proven.

With the owner's approval, the test copy was uninstalled (profile data kept),
the public `Blanc-Setup-1.28.0.exe` was downloaded, matched its published
SHA-256 and a valid `CN=Bananify Creative` Authenticode signature, and was
installed normally to `%LOCALAPPDATA%\Programs\blanc`; the leftover
validation folders were removed. The next release's adjacent Windows handoff
must be confirmed from this normal install, including the automatic reopen and
the taskbar pin.
