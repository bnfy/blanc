# Native iOS Settings

Implemented October 25, 2026. This supersedes F14's shared-page entry point in
the companion-release design; it does not add desktop-only settings to iOS.

Settings is a large native SwiftUI sheet with Browsing, Appearance, Privacy,
Sync, and About sections. The Island shortcut, `/settings`, `/sync`, typed
`blanc://settings/` links, and the site-protection link route here without
adding a tab. The palette dismisses before the sheet is presented. Existing
restored Settings tabs retain the bundled page, bridge, and back history.

## Persistence and appearance

Core settings continue through `TabsManager.applySettingsPatch`: theme affects
the native appearance immediately; search uses the current normalizer; blocker
changes update and reload existing web tabs. Five supported engines are shown.
An existing synced `custom` choice still uses iOS's DuckDuckGo fallback; there is
no custom-template editor in this change.

Layout and appearance use shared manager methods from both the page bridge and
the native controls. The manager broadcasts changes to open Start Pages and
native Settings previews. Previews run the actual bundled Start Page, including
the native clock renderer, but are noninteractive and absent from the session,
history, tab sync, and tab strip. Their references are weak outside the views.

Wallpaper and clock choices retain the existing `start-appearance.json` and
image storage, validation, defaults, font limits, and device-local boundaries.
The photo picker grants access only to the selected photo. Clock controls apply
to Billboard; choosing another layout does not discard the clock preferences.

Allowed sites use the existing normalized host list. Changing an exception
updates protection and reloads only affected open tabs. No new data-clearing,
telemetry, licensing, or purchase controls are introduced.

## Sync

The native UI uses the existing `SyncEngine`, Keychain store, and encrypted
protocol. It supports joining with a pairing/recovery code or existing
name/passphrase, status and errors, device naming, tab sharing, manual refresh,
pairing another device, recovery-code copy, account switching, and disconnect.
Creating an account remains a desktop action.

The presentation model prevents concurrent submissions, retains failed input
for retry, clears secrets after success or dismissal, and ignores late replies
after dismissal. Pairing sessions are revoked on leaving the code screen,
including when its creation was in flight. Account switching and disconnect
require confirmation. Recovery-code copy requires confirmation and uses a
local-only clipboard item expiring after two minutes; the code is never passed
to the web page. Disconnect retains the engine's existing local-data behavior.

## Localization and verification

Native labels reuse the shared copy catalog. New strings are supplied in
English, German, Spanish, French, Italian, and Brazilian Portuguese. Glossary
exceptions cover identical product names, familiar technical terms, and the
example hostname. Generated catalogs remain generated by `copy:build`.

`NativeSettingsTests` covers routing, tab preservation, persistence, preview
isolation and updates, status mapping, retry, concurrent submission, and late
completion. `SettingsUITests` exercises the rendered sheet, preferences,
customization, photo cancellation, allowed sites, localized large text, and
Sync through a DEBUG-only encrypted in-memory service. Test runs use isolated
local storage and do not contact production Sync or use production credentials.

Validation results and any manual accessibility limitations are recorded in the
completion report. This work does not publish a build or change the release
baseline.
