# Blocker seed build preparation

The desktop blocker seed is generated locally rather than stored as a binary
in Git. The filter/resource source files and the seed's hash manifest remain
tracked. The packaged file name and runtime loading behavior are unchanged.

Run `npm ci` (or `npm install`) in a clean checkout. Its `postinstall` step
runs `node adblock/seed.mjs --prepare`. Preparation verifies the pinned inputs,
regenerates the seed, and compares the complete resulting manifest with the
tracked manifest before writing the ignored binary. It cannot silently
approve a dependency or filter change by rewriting that manifest.

If installation intentionally uses `--ignore-scripts`, run
`node adblock/seed.mjs --prepare` before existing blocker checks or packaging.
Existing `npm run adblock:check` continues to require the binary and verifies
its exact regenerated bytes. Existing packaged-payload checks remain required.

For an intentional filter/resource/engine update, review the source and pins,
run `npm run adblock:build`, and commit the updated source inputs and manifest.
If installing changed dependencies first, use `npm ci --ignore-scripts` before
that explicit regeneration. The binary stays ignored. Normal preparation
must then succeed without changing the tracked manifest.

This candidate addresses the OpenSSF generated-artifact requirement by
generating the seed from source during setup. It does not claim that the
currently published release or primary branch has adopted this process.
Native packaging validation remains required before merge/release.
