# Bangs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `!yt lofi` in the Island opens YouTube's results directly, for every search engine, with a hint row, a `!` picker and custom bangs in Settings.

**Architecture:** Kagi's bang list is committed and pinned under `bangs/` and compiled by `bangs/build.mjs` into a generated catalog file; one pure, dependency-free module (`src/renderer/pages/bangs.js`) parses, resolves and matches bangs for both the main process and the overlay. Main is the authority on Enter (`navigateTabToAddress`, `tabs:search`); the overlay only draws the hint row and picker from the same module, and both the overlay and main refuse search suggestions for bang-shaped text. Settings hold the synced switch and custom list and the device-local recents.

**Tech Stack:** Electron main + sandboxed renderers (vanilla JS), `node --test` unit tests, Cucumber + Playwright acceptance, the repository's substrate build/check scripts.

**Spec:** `docs/superpowers/specs/2026-10-16-bangs-design.md`

## Global Constraints

- `src/renderer/pages/bangs.js` has no `require`, no Electron, no Node API and no DOM; it uses the dual-module wrapper of `src/renderer/space-identity.js` (`module.exports` when `module` exists, else `root.Bangs`).
- Catalog entry shape is fixed: `[code, aliases[], name, domain, template, encoding, home]`; templates use `%s`; `encoding` bit 1 = URL-encode the words, bit 2 = spaces as `+`; default `3`; `home` is a normalized `URL.href` (ends in `/`).
- Bang code grammar, one anchored regex shared everywhere: `BANG_CODE = /^[a-z0-9][a-z0-9_-]{0,31}$/i`. A token is `!` + code at the start or the end of the text; the first token wins; codes compare lowercase.
- Custom bang: `{ code, name, template }`; code per the grammar, stored lowercase; name 1–60 characters; template passes `isValidSearchTemplate` (https, or http to a local-network host, exactly one `%s` after host and port, ≤ 2048 chars); at most 100; duplicate codes keep the first.
- `bangsEnabled` (default `true`) and `customBangs` (default `[]`) are in `SYNCED_KEYS`; `recentBangs` (default `[]`, at most 10 primary codes, newest first) is device-local, never written from private tabs, cleared with history.
- No search-suggestion request for text with a bang-shaped token at either end, known or unknown, bangs on or off, in both the overlay and `chrome:search-suggestions`.
- Every new UI string goes in `copy/messages/en.json` and is translated into `de`, `es`, `fr`, `pt-BR` and `it` in the same branch, acknowledged with `npm run copy:ack -- <locale> <keys>`.
- US spelling in everything added.
- Commit after each task; never commit on `main`; work on `claude/blanc-helium-feature-parity-500cb4`.

## Review Focus

1. A code that is both a bang and a word people type with `!` for emphasis (`!important`, `!true`): with a known code, the bang wins; make sure the hint row makes that visible rather than silent. Test in Task 2 (`parseBang('!important css')` resolves only if `important` is a code) and Task 6 (hint row shown).
2. Pasted text with a trailing bang on a new line or with a tab (`lofi\t!yt`): whitespace other than a space must count as a separator. Test in Task 2.
3. A custom bang whose template points at a local `http://` server with a port: the empty query must open `http://host:port/`, not `https://host`. Test in Task 2.
4. Turning bangs off while the panel is open with `!yt lofi` typed: Enter must search the literal text and the hint row must leave without a relaunch. Test in Task 6 (vm) and Task 10 (acceptance).
5. A custom-bang list arriving from sync with junk entries (wrong types, 200 items, an `http://` internet template): `getSettings()` must return only valid rows and never throw. Test in Task 3.
