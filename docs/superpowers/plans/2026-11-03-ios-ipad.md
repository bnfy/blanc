# Blanc for iPad — plan

**Date:** 2026-11-03
**Status:** Draft for the owner. Nothing here is built. The owner skipped the
design questions, so every choice below is Claude's call unless it says
otherwise. §7 lists the choices that are the owner's.
**Builds on:** [iPhone Duo design](../specs/2026-10-21-ios-iphone-duo-design.md)
(the "size class, never device" rule), [Duo-1 regular Island](../specs/2026-10-29-ios-duo-1-regular-island-design.md),
`spec/divergence-register.md` D7 (keyboard), D11 (window model), D30 (regular
width).

## 1. Where the app stands today

- **The app targets iPhone only.** `TARGETED_DEVICE_FAMILY = 1` for the Blanc
  and BlancShare targets in `ios/Blanc/Blanc.xcodeproj` (only the test targets
  say `1,2`). On an iPad the App Store would offer it as an iPhone app in
  compatibility mode.
- **1.0 is in App Review** (build 202611030537, iPhone only, manual release).
- **Most of the iPad layout already exists.** Duo-1 (#1275) picks the layout by
  size class in `IslandLayout.swift`: regular in both directions gets the
  unfolded Island (Back/Forward, capped width, the palette as a panel growing
  up from the Island). An iPad full screen is regular × regular, so it would
  get that layout with no device check.
- **Built since this plan was written (2026-11-03):** Split View
  (bnfy/blanc#1325) and floating Glance (bnfy/blanc#1327), in the wide layout.
  See iPad-2 below.
- **Not built yet:** hardware-keyboard shortcuts (only two `.keyboardShortcut(.cancelAction)`
  calls in `ContentView.swift`), pointer hover, and multiple windows. The
  app has a single `WindowGroup` in `BlancApp.swift`, and
  `UIApplicationSupportsMultipleScenes` isn't set.

## 2. Principles

1. **One app, chosen by size class.** No `userInterfaceIdiom == .pad` checks in
   layout. An iPad window can be any size now (iPadOS 26 windowing), so the
   iPad is just "a window whose size class changes a lot." Device checks are
   allowed only for things that really depend on the device (copy that names
   it, the device name sent to sync).
2. **Resizing never costs state.** Resizing, rotating, and moving a window
   between full screen and windowed re-parent web views and never reload
   them. This is the same rule as folding the Duo.
3. **The Island stays the Island.** No tab strip or toolbar. The iPad gets more
   of the desktop's surfaces (shortcuts, Split View, Glance, windows), not a
   different product.
4. **Shared work lands once.** Split View and Glance are Duo-2. Built for
   regular width, they serve the Duo and the iPad together.

## 3. Milestones

| Step | What it delivers | Ships in |
|---|---|---|
| **iPad-1** | A real iPad app: device family 1,2, every orientation, the regular layout tuned for iPad sizes, keyboard shortcuts, pointer, iPad in CI, App Store iPad screenshots | 1.1, after 1.0 is released |
| **iPad-2 = Duo-2** | Split View (two panes) and floating Glance in regular width; Swift `SplitModel`; splits saved in the session. Built: #1325, #1327 | With iPad-1 (it's already on main) |
| **iPad-3** | Multiple windows (F32): each window has its own workspace; drag a tab out into a new window; works with Stage Manager and the iPadOS 26 window system | 1.3 or later |
| **Later** | The side list from Duo-3, drag and drop of links and tabs between apps, external display | after iPad-3 |

### iPad-1: a real iPad app

**Build settings**
- `TARGETED_DEVICE_FAMILY = "1,2"` for Blanc and BlancShare (Debug and
  Release). Keep `SUPPORTS_MACCATALYST = NO`, and leave the "Designed for
  iPad" Mac/Vision options off.
- `UISupportedInterfaceOrientations~ipad`: all four. Don't set
  `UIRequiresFullScreen`: it would block windowing, and Apple deprecated it
  with the iPadOS 26 window system (check the current documentation before
  relying on that).
- Make sure the launch screen and the `.icon` app icons render on iPad. The
  Liquid Glass spec already saw `AppIcon76x76@2x~ipad.png` written. Alternate
  icons in Settings → Appearance need a check on iPad.

**Layout across window sizes**
- Check every surface at these sizes: 13" and 11" full screen in both
  orientations, half-screen, a small window (about 500 × 400 pt), and the
  narrowest window iPadOS allows. Compact width has to get the iPhone layout
  and look right. Compact height in regular width (a short, wide window) has
  to keep the Island off the keyboard.
- The Island's capped width comes from the readable-content width (Duo-1).
  Check it doesn't look lost in the middle of a 13" landscape screen. If it
  does, raise the cap; never stretch it edge to edge.
- Sheets: Duo-1 found that a stock `.sheet` turns into a form sheet pinned
  top-left in regular width. Go through every sheet (Settings, Spaces, Shared
  Spaces, Bring Space, Pair, Walkthrough, Wallpaper, Group name, App icon)
  and choose on purpose: a centred form sheet with `presentationSizing`, a
  popover anchored to the control that opened it (the Island menu, the
  shield), or full screen.
- Tab grid (`TabGridView`): more columns in regular width, previews rendered
  at the iPad size (`TabPreviewRenderer`).
- The start page (Ledger, Billboard, Shelf, Tally; `NativeClockOverlay`) at
  iPad sizes: the clock's type scales, wallpapers fill without stretching.

**Web content**
- WebKit asks for desktop sites on an iPad by default. Keep that as the
  default, and add a per-site **Request Mobile Website** / **Request Desktop
  Website** toggle using `WKWebpagePreferences.preferredContentMode`. The app
  sets no content mode or custom user agent today. This is the one place a
  device check makes sense.
- Content blocking (`ContentBlocker`), Reader Mode, and pull to refresh: no
  change expected. Check them on the iPad simulator.

**Hardware keyboard (D7's iPad allowance)**
- Add a SwiftUI `.commands` menu, which also shows the ⌘-hold overlay, with the
  desktop's shortcuts for actions that already exist on iOS: ⌘L (palette),
  ⌘T, ⌘⇧N (private), ⌘W, ⌘⇧T (reopen closed), ⌘R, ⌘[ / ⌘], ⌘F, ⌘D, ⌘Y,
  ⌘⌥B, ⌘,, ⌘1–9 (nth tab or group, using the desktop's cluster rule),
  Ctrl+Tab / Ctrl+⇧Tab (by position; most-recent order is a later step),
  ⌘+/−/0 (zoom), Esc (closes the palette or find).
- Typing in the palette: ↑/↓ move through rows, Return opens, ⌘Return opens in
  the background.
- A shortcut a focused web page already uses goes to the page first, except
  ⌘L, ⌘T, ⌘W, and ⌘⇧T, which Blanc keeps (the desktop's rule).
- Add the shortcuts to `spec/` (D7: iPad shortcuts shipped) and to the
  in-app shortcuts list if iOS shows one.

**Pointer and trackpad**
- Hover effects (`.hoverEffect`) on Island buttons, tab dots, palette rows, and
  tab grid cards. Secondary click opens the same context menus as long-press
  (F19). Two-finger swipe on the Island does what the Island swipe does.

**Things that name the iPhone**
- iOS copy that says "iPhone" (walkthrough, pairing, settings) has to name the
  device it's running on. Use `UIDevice.current.model`-style wording only for
  copy, never for layout.
- Desktop copy: "Connect your iPhone" and the pairing flow in `src/main`
  (`pages.js`, `settings.js`, `sync-changes.js`, `migration-checklist.js`) and
  `copy/messages/*.json`. Change to "iPhone or iPad" only once an iPad build is
  public (marketing-claims rule). Every language changes in the same PR, and
  `copy:ack` runs for each one.
- Sync device names and the Other devices list: an iPad shows as an iPad, not
  as an iPhone.
- `LaunchPing` / first-minute telemetry: report the device family so iPad
  installs can be counted. That needs a new allowed value in the ping Worker,
  reviewed like any Worker change.

**Share extension, pairing, background refresh**
- BlancShare on iPad (share sheet from Safari, Files, Notes).
- `PairScanner` with the iPad's camera, including landscape and the
  front-camera-only iPads; paste a code by hand as the fallback.
- `BackgroundRefresh` behaves the same.

**CI and checks**
- `.github/workflows/ios.yml`: run the unit and UI tests on an iPad simulator
  (an 11" iPad Pro) as well as the iPhone. Keep the UI tests to a
  regular-layout smoke at first: open the palette, open a tab, switch tabs,
  rotate, resize. Only add tests the iPad needs.
- A UI test that resizes the window (iPadOS 26 lets XCUITest drive windowed
  apps) and checks that a playing video keeps playing and a half-filled form
  keeps its text.
- A hands-on check on a real iPad before any public claim (the owner's
  device or TestFlight).

**App Store**
- iPad screenshots (13" required) through the same capture flow as the 1.0
  set, with the same rules (no Wikipedia, real UI only). An optional iPad
  preview video.
- The listing text and `docs/ios/app-store-listing.md`: say iPad only once
  1.1 is approved.
- Once an app version on the App Store supports iPad, later versions can't
  drop iPad. That's why iPad-1 waits until 1.0 is out and 1.1 is ready.

**Spec updates**
- Add **D32 — iPad**, or widen D30 to "regular width on iOS (Duo inner display
  and iPad)". Note the keyboard shortcuts (D7), pointer, and the
  desktop-site default. Update the iOS column in `spec/parity-matrix.md`.

**Acceptance for iPad-1**
- On a 13" and an 11" iPad simulator, and then a real iPad: no letterboxing in
  any orientation or window size. Rotating or resizing with three tabs (one
  playing video, one with a half-filled form) reloads nothing.
- Every sheet looks deliberate in regular width, and compact width looks
  exactly like the iPhone.
- Every listed shortcut works with a hardware keyboard and shows in the ⌘-hold
  overlay.
- An iPhone looks and behaves exactly as before (the existing UI tests pass
  unchanged).

### iPad-2 = Duo-2: Split View and Glance

Built on 2026-11-03 for the wide layout (regular in both directions), so the
unfolded Duo and the iPad share it. It was checked on an iPad Pro 11-inch
simulator (iOS 27.2) using a local build with iPad turned on.

**Split View (bnfy/blanc#1325)**
- `SplitModel.swift` ports `src/main/split-model.js`: two panes, the
  initiator's group wins, and a split moves into and out of groups as one item.
- Closing a pane leaves the other pane current. Close Split is one Undo.
- Splits are saved with the session and Spaces (`splits` + `splitIds` on
  `SavedSet`) and are never synced.
- A tab's menu in the tab grid and palette has **Split with ▸**, **Remove from
  Split** and **Close Split**.
- Panes are rounded cards, each with a corner tab (site and ×), and a
  draggable divider sits between them. Touching a pane focuses it.
- A narrower window shows the focused pane alone, and the split comes back
  when the window widens again.

**Glance (bnfy/blanc#1327)**
- The page is an ordinary tab shown in a card floating over the current page.
  The card moves by its header and resizes by its corner grip
  (`GlanceGeometry` ports `glance-card.js`).
- Its header has **Open as tab**, **Keep as split** and ×. × leaves the tab
  open (owner, 2026-11-03: keep desktop's behavior).
- It opens from a link's menu (**Open Link in Glance**), a tab's menu in the
  tab grid and palette (**Open in Glance**), and the Island's Sunrise menu
  (**Open in Glance ▸** lists the other tabs; **Close Glance** while a card is
  open).
- A tab switch, a split or a narrower window ends it.

**Still to do for iPad-2**
- Keyboard: ⌘⌥←/→ to move focus between panes, and a shortcut to open and
  close Glance (desktop's `menu.toggleGlance`). This belongs with iPad-1's
  shortcut work.
- Remember the Glance card's frame across launches (desktop saves
  `glanceFrame` in device-local settings).
- Show a split as one joined card in the tab grid and palette.
- Draw the focus mark on the Glance card.
- Duo only: snap the divider to the fold and keep the card off it while
  part-folded (`reservedRegions`, iOS 27.1).
- On a 13" iPad, consider a three-column split behind a width threshold. The
  default stays at two (D30). It's the owner's call whether to offer it.

### iPad-3: multiple windows

The largest step: today one `TabsManager` owns everything. Moving to windows
means:
- Set `UIApplicationSupportsMultipleScenes = YES`. Each scene gets its own
  workspace: tabs, tab order, groups, active tab, Recently closed. That
  matches the desktop's per-window runtime (`window-runtime-registry.js`).
- `SessionStore` saves one entry per window, like the desktop's session.json
  v2 `windows[]`, and restores each window into its own scene through
  `NSUserActivity` / scene session restoration.
- Spaces: one Space per window, as on desktop. A Space that's open in one
  window can't be opened in another. Spaces sync keeps working per window.
- Opening a new window: ⌘N, "Open in New Window" in the tab menu, dragging a
  tab out of the tab grid or the palette, and the system's "Show All Windows."
- Links from other apps (`IncomingLinks`) go to the most recently active
  window, as `resolveExternalRuntime` does on desktop.
- Private tabs stay in memory per window. They're never saved.
- The process-wide pieces stay shared: favorites, history, settings, sync,
  content blocker.

This needs its own design spec before any code: the scene/workspace split
touches nearly every store.

1. Branch from main after 1.0 is approved, so the App Review build doesn't
   change underneath it.

9. TestFlight build. The owner checks it on a real iPad.

Each numbered step is about one PR. Steps 3–7 don't depend on each other, so
they can run in parallel once step 2 lands.

## 5. Risks

- **Window sizes iPadOS allows are more varied than the Duo's two displays.**
  Size class flips while the person drags a window edge. The layout switch
  has to hold up under rapid flips without re-creating web views (Duo-1's
  re-parenting rule; test it with a scripted resize).
- **Memory.** iPads keep more tabs alive, but WebKit still evicts content
  processes. No change to the tab lifecycle (D8); just check the crash
  recovery path on iPad.
- **Keyboard conflicts** with web apps (Google Docs, Figma). The page-first
  rule above handles most. Check the common ones by hand.
- **Default browser.** The default-browser entitlement request covers the
  bundle, not the device, so iPad needs nothing new. Confirm this when Apple
  answers the pending request.

## 6. Not doing

- A Mac Catalyst or "Designed for iPad" Mac build. The Mac has the desktop app.
- A tab strip, sidebar by default, or any chrome that replaces the Island.
- Apple Pencil–specific features beyond what the system gives for free
  (Scribble in text fields works already).
- Device-model checks in layout.

## 7. The owner's calls

1. **When iPad ships:** in 1.1 right after 1.0 (recommended). Split View and
   Glance (iPad-2) are now built, so the first iPad release would already
   have them.
2. **Whether multiple windows are required for the first iPad release.**
   Recommended: no. Ship iPad-1, then windows. Many iPad users will expect
   windows, though.
3. **A three-column split on a 13" iPad** (iPad-2), against D30's two-pane
   rule.
4. **iPad screenshots and listing text** need sign-off, as the 1.0 set did.
5. **Which iPad does the hands-on check.** Is there an iPad available, or
   should the first external TestFlight testers cover it?
