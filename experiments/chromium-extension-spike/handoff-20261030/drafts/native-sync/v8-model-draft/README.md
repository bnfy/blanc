# Native shipping-model runtime exploration

Chromium already ships Gin/V8. The standalone proof reuses its cached arm64 objects and matching snapshot/ICU, with one newly compiled diagnostic unit. It does not start an app/dependency build or change browser-process initialization. The exact verified released tabsync-model.js is embedded by stage-model.mjs with source/header hashes, a lexical module wrapper and native UTF8 byte-length callback. No Buffer/Node runtime, DOM, network, filesystem or credential API is supplied to the isolate. Trusted source compiles before string code generation is disabled. This is a diagnostic, not the production sandbox or an integrated runtime.

Native V8 JSON preserves escaped lone surrogates. The actual released sanitizer produces byte-identical JSON to Node24 for device-name/title UTF16 cuts that leave lone high surrogates. The native byte-length callback counts the lone surrogate as three UTF8 bytes, matching Node. Comparison commands and logs are in outer evidence/native-sync-v8-model-20261030.

This offers a path to reusing shipping canonical/Unicode/number semantics rather than writing another JSON/model implementation. Production choice still needs a dedicated owner/process boundary, existing Gin initialization coordination, bounded memory/execution and failure handling, asynchronous model-plan adapter, exact-source resource packaging and cross-platform acceptance. Chromium's proxy_resolver_v8.cc provides an existing utility-isolate/initialization reference. Do not change global V8 flags in an already initialized browser. Keep keys and provider APIs outside the model runtime. Raw wire data must be parsed as JSON, never compiled as script.

The current BlobExchange strict JSON validation has NOT been replaced. The known lone-surrogate gap remains open. No browser parity credit, Profile/UI integration, dev refresh or real network/credentials occurred.

model_runner.{h,cc} now provides a draft owned single-thread actor. Native callers select a fixed enum; JSON input is never compiled. Prior Gin initialization is mandatory, and only the diagnostic test configures startup flags. Results are posted to the caller's sequence and redacted after shutdown; isolate disposal runs on its owner, including repeated shutdown completion ordering. The departure helper is a pure projection of released sync.js's devices replacement with a native clock/validated own UUID, not a completed retraction transport. Tests also cover JS number overflow/rounding, invalid JSON and lossless peer Unicode. Draft1MiB bounds are not full local-cache size acceptance. Utility-process heap/watchdog isolation, async exchange adaptation and production profile/model/size qualification remain.

departure_adapter.{h,cc} now connects the runner to BlobModelHooks.plan_async. Remote JSON is transported as a string field and parsed separately inside the fixed departure operation, preserving surrogate data while protecting native metadata. The encrypted async fake-server fixture passed6 scenarios plus8 synchronous-path regression scenarios. Keys stay outside the VM; cancellation is rechecked on the exchange's owner sequence after planning. Bounded disable/departure scheduling and production runtime/factory wiring are still absent.
