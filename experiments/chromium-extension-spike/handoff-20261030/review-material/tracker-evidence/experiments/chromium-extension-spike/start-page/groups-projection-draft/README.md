GitHub's latest release endpoint was checked on October 29: [v1.45.0](https://github.com/bnfy/blanc/releases/tag/v1.45.0), published from `6f1bc523d2f0d432d5c4119b9f7ec22a324dbd2d`. Its `src/main/main.js` Start Page groups hook enumerates the current window's clusters in order, exposes group id/name/color and a count of non-private members, and omits groups with no regular members. Its `focusGroup` unfolds the group and activates its first tab. The shipping Start Page renders its existing group chips in all four layouts. In shipping's mixed regular/private window model, a private Start Page can receive that window's non-private group projection; private-only groups are filtered. This source reading does not constitute a new observation of the installed shipping app.

The current development adapter returns `groups: []` and has no `focusGroup` implementation. `ui-candidate.cc` and `newtab-adapter-candidate.js` are isolated copies based on the current 158 source and verified development assets; `inputs.json` records base/candidate hashes. The draft adds Start Page-native groupsRead and focusGroup to the existing exact-primary-frame `IsStartPage()` bridge. Each request resolves the actual browser owning that Start Page, requires the same regular profile, reads only that window's native groups in tab order, and re-resolves the requested group within that model before acting. Focus also requires the Start Page to be the active WebContents, unfolds a collapsed group and selects its first tab. The private page requests and receives no group projection and cannot focus a group. This is a deliberate, narrower privacy behavior than shipping's mixed-window private page; native Chromium uses separate regular/private windows and no regular-profile group information is imported into a private one. Other guest/system off-record pages remain subject to the existing trusted-page gate and receive no projection. Do not describe this as full private parity.

Group reads run independently of initial Start Page data and the existing refresh queue, after data is ready. At most one request is in flight, with a 1.5-second timeout; visible regular pages refresh once per second and on visibility restoration. Private or hidden pages send none. The group-focus epoch rejects stale in-flight replies. A failed/malformed read clears actionable group chips and shows a localized unavailable status and Retry button; if a focused group disappears, focus moves to Retry. An unchanged normalized snapshot does not repaint; a real change touches only group elements, restores focus to the same group ID when possible, and otherwise moves it to the always-visible Start Page content. Synthetic checks exercise this behavior in all four layouts. These are not a substitute for real keyboard/VoiceOver checks.

For action safety the native draft requires an active, visible, non-minimized owning window and active Start Page. Group visuals changes can synchronously notify observers, so it takes weak pointers and, after unfolding, re-finds the owning browser, profile, live tab strip, active window and group/index before activation; it checks handler liveness after activation. The actual observer lifecycle and `BrowserView` API are not compiled or browser-tested. A split-pane Start Page that is not the active WebContents cannot focus a group in this draft; this may be stricter than shipping. Polling differs from shipping's event-driven updates and can lag by a polling period.

`adapter.test.cjs` exercises the isolated adapter against fake native replies: non-blocking data load, bounded non-overlapping group reads, private/hidden no-read, malformed responses, failure clearing and stale in-flight rejection. `renderer.test.cjs` checks unchanged-snapshot suppression, group-only redraw, stable-ID focus restoration and failure/retry focus across four fake layouts. `node --check` passes for both candidate scripts. These are synthetic JavaScript checks, not native authority, rendered parity, or browser evidence. No native compile or actual browser test was run. No production source, app, profile, caches, signed artifact or Google baseline was modified. Native compilation against the actual checkout, active/hidden/closing window behavior, group move/removal races, tab strip destruction, observer/lifecycle behavior, private and guest boundaries, dynamic updates, all layouts, keyboard/VoiceOver, visual comparison to installed shipping, and default/forced-color settings all remain open. Reconcile with newer source/asset changes and review private scope before any staging; run a guarded incremental dry run before any build.

Strict cached-flag native syntax compilation passed with `-Werror -fsyntax-only`; `syntax-command.json` and `syntax.log` preserve the exact inputs and output. The separate 78-file asset candidate, unrun regular/private browser fixture, and guarded staging plan are documented in `fixture-and-staging-plan.md`. Syntax and synthetic checks do not establish runtime parity.
