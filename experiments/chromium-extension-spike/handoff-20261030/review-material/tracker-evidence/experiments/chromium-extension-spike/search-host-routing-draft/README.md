# Host-bound selected search routing candidate

Unstaged prototype based on Chromium 158 source SHA `75a8c1f7dd6f7488b35350628883a022424dd46b5ea462670dd9265127626070` and current development `assets-v1` host SHA `e14ec051f395e3f1189ab8a637d01988b90fb88260cb7e6f8593091d734a167e`. Latest shipping reference reverified as v1.45.0 / `6f1bc523d2f0d432d5c4119b9f7ec22a324dbd2d`. `prepare.py` creates independent candidate files and records hashes; the canonical source and actual Chromium workspace were not staged.

The candidate retains the existing Island HTML/keyboard control. Host text classified as search and explicit search rows ask native code to resolve the effective selected provider rather than hardcode Google. The native request requires the same active tab, browser-owned selection epoch and primary document, no pending navigation, and repeats those checks after provider resolution. Observer code reports commit, same-document, failure, or unknown for the original tab. Exact known stock fallback uses its effective selection; this preserves current choices and configured overrides but does **not** initialize fresh profiles to the shipping DuckDuckGo default. Unknown, extension-controlled, unsupported or loading providers return an unavailable result rather than silently choosing Google. User-selected custom and effective policy literal templates use the prior validator. Existing HTTP(S) URL navigation is retained; bare localhost and IPv4 use HTTP, Unicode domains navigate as HTTPS, known OS protocols use native handoff with a neutral result, and explicit local-file/UNC and unsupported URL schemes are rejected without provider transmission. Relative ambiguous text such as `foo/bar` still follows shipping's search classification and is not proven private when it happens to name a local path.

`createSearchTab` captures the newly inserted WebContents via a temporary TabStrip observer and matches it against the `AddAndReturnTabAt` result before using it; it observes the exact new tab's navigation and reports its tab ID and selection epoch with commit, failure or unknown. Normal `createTab` also returns the safely captured created tab ID and epoch while retaining its existing dispatch-only completion. Overlay submissions retain the input until an outcome arrives, and accept an expected creation transition only when its browser-owned epoch and returned tab ID match. Additional or ABA tab transitions invalidate the pending response. A post-creation error before an identity can be returned may preserve the panel without displaying an error; this remains open. The candidate does not port bangs, full URL/local-file/external-protocol behavior, Settings defaults, onboarding, Sync or search suggestions.
