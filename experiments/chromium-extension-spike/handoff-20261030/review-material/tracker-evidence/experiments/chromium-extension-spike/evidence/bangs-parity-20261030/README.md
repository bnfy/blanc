## Remaining implementation

Reuse the released pure parser, catalog and Island picker, but connect them to a native, profile-owned authoritative settings/recents service and validate custom templates. The native navigation boundary must resolve typed text against the same current state and selected search engine; it must not trust a stale UI hint. Preserve private recents isolation, device-local recents/history clearing, synced switch/custom settings, provider-suggestion suppression in both UI and native boundary, live cross-window updates, safe URL validation and native navigation security. Implement the actual Settings controls and migration, then exercise regular/private, aliases, empty query, unknown and disabled bangs, custom validation, history clearing, cross-window/sync, keyboard/picker and desktop platform/accessibility behavior. The present tests show a gap; they are not a fix and do not qualify a fallback that silently omits settings or privacy behavior.
