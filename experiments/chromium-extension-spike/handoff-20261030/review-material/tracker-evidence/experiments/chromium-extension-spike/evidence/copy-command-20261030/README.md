# Copy commands in Chromium candidate

Shipping reference verified 2026-10-30: Blanc v1.45.1, source `85883b1afa11375e1300130914d6f40c5388af21`. Its `/copy` copies the current pane URL; `/copy clean` removes tracking query parameters, retains other URL bytes, and briefly confirms in the Island. Chromium native tab-copy support was selected over reimplementing clipboard or URL-policy enforcement. Canonical `prototype/host.js` now binds `copyActiveLink` to the focused pane's captured tab ID and visible URL; native `copyTabLink` revalidates window ownership, committed URL and pending navigation before writing. Failed or unsupported targets do not display success. The existing released cleaner is reused.

`stage.cjs` verifies all 78 v37 input assets and assembles a separate candidate with changes only to host, overlay, renderer and the English catalog. It ports the released command and pill confirmation, using the exact three English messages from the published source. The staged candidate requires framework `49b25ce10ef94d20f2dee38594bd7568a00fd67000647f655214def66e40f35b`; asset manifest SHA-256 `5c6d161d78aa70a38b33455a5651dd4c04e0b5dba5f1644dfa125b411e706e4e`. This is not compatible with the older development framework without its native copy handler.

In isolated regular and verified non-default private browser contexts, the script-driven `/copy` and `/copy clean` rows copied the local page URL and correctly removed `utm_source` while preserving the other encoded query bytes and fragment. Each displayed the matching confirmation and the confirmation cleared. Two owned browsers exited zero and successful fixture profiles were removed. The clipboard-preserving Swift wrapper restored the original representations from memory only after confirming the test value remained; no original clipboard data was saved or logged. Raw receipt `Chromium Preview/evidence/copy-command-20261030/check-v1.json` and manifest are durable.

No user development browser, permanent profile, app binary, native source/output or signed artifact was changed. This candidate has not been promoted: its v37 base contains other changes and selected-search outbound isolation is still unresolved. The focused 158 preparation path does not yet include this command; do not expose it against a framework lacking `copyTabLink`. Non-English catalog integration, cross-window/focused split and stale-target command races, real physical input, screen reader/visual and Windows/Linux qualification remain open. Existing native stale-link test used an earlier framework, not these exact bytes.
