# Native Settings tab reuse

Shipping reference: Blanc v1.45.1 source `85883b1afa11375e1300130914d6f40c5388af21`. Shipping opens a Settings utility sheet; the Chromium prototype uses native Settings, as allowed for Settings appearance, but previously created another tab on every open. The canonical host now checks the current window for an existing regular `chrome://settings/` tab, focuses it if present, and coalesces concurrent requests. If that tab disappears or navigates while selection is in flight, it opens a fresh Settings tab rather than navigating the changed tab. Private routing retains Chromium's separate regular-window behavior, which is not shipping parity.

The isolated candidate `Chromium Preview/artifacts/settings-reuse-candidate-20261030` differs from the prior scoped-tested `/settings` candidate only in `host.js`; its 78-file manifest SHA-256 is `67552e6f4ca59223cc348f79b358403c2771a8eca4db26c19331ea5487b1f602`, framework `237242c7e2ddfab4d8fa49528b98a130c1e11dff9f80ffa1db39c0cdc8c06fa1`. Regular scripted UI test opens Settings, changes tabs, reopens `/settings` and verifies the original tab is focused without a duplicate; simultaneous native host requests also leave one. Private scripted test confirms Settings still opens in a separate regular window without moving the private fixture page into that window. Both owned processes exited zero and passed profiles were removed.
