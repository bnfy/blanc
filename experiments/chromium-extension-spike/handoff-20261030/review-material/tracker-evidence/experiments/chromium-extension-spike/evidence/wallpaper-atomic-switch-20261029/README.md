# Start Page wallpaper switch: atomic preference write

Shipping reference rechecked 2026-10-29: GitHub latest Blanc v1.45.0, tag commit `6f1bc523d2f0d432d5c4119b9f7ec22a324dbd2d`. The released `src/main/pages.js` changes the custom-wallpaper setting only after an image import succeeds.

The Chromium prototype previously disabled the installed Store theme in one `localStorage` write and then saved the chosen wallpaper in a second. If the second write failed, the theme could be disabled without the requested wallpaper being stored. `prototype/newtab-adapter.js` now writes both changes together for custom, color, Sunrise and time-of-day selections. Existing saved preferences and other adapter behavior are preserved.

Verification: `node --check experiments/chromium-extension-spike/prototype/newtab-adapter.js` passed. `node experiments/chromium-extension-spike/evidence/wallpaper-atomic-switch-20261029/atomic-switch.test.cjs` passed against the actual adapter in a simulated DOM and storage environment: color and time-of-day selection each produce one preference write, and a failed custom-image storage write does not disable the theme or publish an update. Those hashes were the initial source/test before the selector fix described below; current hashes are recorded below.

That initial VM check was not an actual browser, file-picker, installed theme, private-profile, persistence-restart, accessibility or cross-platform test. The later scoped browser checks are described below; full wallpaper parity and a development-browser refresh remain open.

## Larger image acceptance and compression fallback

Shipping accepts JPEG/PNG input up to 25 MiB and normally writes JPEG at quality 85. A fresh isolated regular 158 fixture accepted a synthetic 2000×1600 PNG of 10,129,425 bytes (`browser-large-image-v1.json`). A distinct 2500×2000 PNG of 15,826,617 bytes failed with `too-large` (`browser-large-image-v2.json`, SHA `b40e4dbd97a4c71b4d71fa5a6bfaca8dd0e5cae194c5ee4304427bce8b09ccb9`); its owned browser exited 0 and failure profile was retained. The prototype imposed a 3 MiB data-URL limit after JPEG encoding, in addition to the input limit.

The prototype now tries quality 0.85 first and, only if the encoded data exceeds that limit, retries at 0.75, 0.65, 0.55 and 0.45. The same targeted patch was applied to the newer groups candidate, preserving its other assets. The affected fresh browser check `browser-large-image-v3.json` passed with the previously rejected synthetic image; its owned browser exited 0 and passed profile was removed. Result SHA `12dfd5555de40d26ce543a808434f3edf58caa1f189e3fa5b8d1203420f5adf7`, candidate asset-manifest SHA `4d7d21a7c65d271a202b13009923eff8b37449c8e0bfb5e0b612b671289160ea`, candidate adapter SHA `3b4acb11dd9d0489ae2db8bf52dfd44b19d151f56161638663e78875ecc94052`.
