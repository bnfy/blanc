# Launch Sunrise renderer candidate — October 29

GitHub's latest release endpoint returned Blanc v1.45.0 with target commit `6f1bc523d2f0d432d5c4119b9f7ec22a324dbd2d`. The released launch Sunrise is off by default, is local to the device, and may be granted to the first visible, non-private Start Page during the first 30 seconds of a launch. It displays over the finished page, skips reduced-motion users, and dismisses on page key, pointer input or animation completion. Main owns the once-only grant and a page gets only its first data request as a chance; an ineligible page does not spend the shared grant.

The **isolated**, unpromoted `Chromium Preview/evidence/start-page-sunrise-20261029/assets-v1` adds the exact released scene markup, animation CSS and image to the active v7a Start Page asset set. Its renderer accepts an exact `launchSunrise: true` boolean only from its initial data response. Existing prototype recovery uses `Promise.allSettled`; this candidate requires all three initial data sources to succeed before drawing the overlay so a partial Start Page is not masked by an animation. That is a deliberate difference from released `Promise.all`, which does not proceed on failure. The asset manifest is `Chromium Preview/evidence/start-page-sunrise-20261029/manifest-v1.json`.

`renderer.test.cjs` passed five focused checks for reduced motion, ignored child-animation events, both dismissal events, listener cleanup and the renderer grant gate. `synthetic1.json` records actual isolated Chromium browser checks on framework `471c507b4e93f0610401d9ded3b4bd11fe0b814b2a79ac26e34f95a881a2fb4e`: emulated reduced motion and a false synthetic grant suppress the scene; a synthetic true grant displays a non-intercepting, accessibility-hidden overlay; CDP pointer and keyboard events dismiss it. `animation1.json` separately verifies normal animation completion removes the overlay. Both fixtures exited normally, used fresh isolated profiles and did not change the open development profile. This synthetic grant proves only the renderer path; it is not a native once-per-launch grant, persisted preference, keyboard accessibility review, cross-platform verification or complete visual parity. No native service or settings were added here; the candidate is not yet a usable product feature.

To integrate, the browser process needs a durable local-only, default-false Appearance setting, trusted document validation, a first-request record for the lifetime of each `WebContents` (matching shipping's `wc.id` set even across navigation), a 30-second launch window, browser-owned visible and non-private eligibility, an atomic process-wide grant, and the `start.data` projection. The setting's real write/restart/error semantics and first-page, background/private, multiwindow/race, navigation/reload, expiration and reduced-motion cases require native/browser verification before promotion. A product must not use the synthetic bridge patch or silently imply the option is available. Full visual review remains separate from the above passed cases.
