## What this counts

Supplemental rows can overlap matrix rows. 57 is a checklist denominator, not a complete independent feature decomposition or a schedule estimate. Two matrix rows marked desktop N/A are excluded: F24, F56. F40 is planned in the release matrix and is included conservatively pending a current shipping-scope audit. The Settings-only visual flexibility is retained; uBO and Widevine remain possible exceptions, not waived. The 57-item set is not proof that the matrix covers every shipping behavior; uncovered requirements must be added when discovered.

**Verified complete** requires exact shipping comparison and real behavior, safety, input, visual and accessibility evidence on each required desktop platform. **Partial evidence** records concrete scoped progress without asserting completeness. **Known gap** means an observed requirement is missing or only drafted; **unassessed** is unknown, not a claim that a feature is missing. Evidence is linked per row; historical results may concern earlier development identities and cannot be transferred silently.

## Updating this tracker

Update [progress.json](progress.json) and its per-row evidence after each meaningful change, then run `node experiments/chromium-extension-spike/evidence/parity-progress-20261029/render-progress.mjs`. Use `--check` to validate the generated document. Do not promote a row to verified without platform-specific candidate identity, shipping comparison, visual/input/accessibility evidence, and evidence paths for all three platforms. Re-baseline the matrix and new release requirements before reporting a newer shipping version. This generator checks the pinned matrix and evidence paths; it does not run tests or decide statuses.
