# Custom tab names: shipping and Chromium source comparison

On 2026-10-29 GitHub reported shipping v1.45.0 at `6f1bc523d2f0d432d5c4119b9f7ec22a324dbd2d`. Its `src/main/tab-name.js` (SHA-256 `9c84fb13b59357ed8ec27dde375979c5c64c17b21089ec012e5cf6fdff2cc4c8`) folds whitespace and control characters, limits names to 100 Unicode code points, handles reset, and avoids freezing an unchanged page-title prefill. Shipping projects page titles separately, carries the name through session/closed-tab/archive data and keeps History/Favorites tied to the page title. Its private tabs must not persist names.

Static inspection of repository `prototype/host.js` and `native/blanc_prototype_ui.cc` finds group rename handling but no tab-rename bridge; snapshots draw WebContents page titles. This is a source-level gap, not an interactive browser test or a full platform audit.

Chromium 158 provides session extra-data machinery: its `SessionService::AddTabExtraData` writes per-tab values; `BrowserLiveTabContext::GetExtraDataForTab` already adds Blanc tab identity and split metadata for closed-tab restoration; `session_restore.cc` already restores Blanc identity from extra data. Those are candidate integration points, not proof they handle custom names, private tabs, sync, archive, split/group/window moves or restore correctly. A product port must share shipping normalization and reset semantics, persist only regular tabs, expose rename/reset through the Island with the existing shipping prompt and menu behavior, preserve the page title for History/Favorites, and verify all lifecycle paths and platforms. No implementation, build, browser interaction or personal profile changes were made in this inspection.

They cover whitespace/NEL/control removal, Unicode whitespace, surrogate-pair truncation, trailing-space truncation, unchanged page-title prefill, unchanged existing name, reset and rename. This is a native rules check, not runtime browser, differential corpus or feature acceptance.
