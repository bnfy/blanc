# Native Blanc Sync integration

Shipping reference: v1.45.1, source85883b1afa11375e1300130914d6f40c5388af21, reverified before this work. `dependencies.json` pins the released backend modules. The current prototype still returns an empty remote-tab list and has no complete Sync/Shared Spaces backend.

## Implementation direction

Retain Blanc's existing encrypted protocol and interoperability with existing accounts/devices. Chromium Google Sync would change the product and is not a substitute. Use native Chromium transport, profile storage and secure OS credential providers; do not bundle Electron or a Node runtime into the replacement.

The first implementation is `native/sync/request_scheduler.h`: a sequence-confined, I/O-free scheduling core. A standalone probe compiled with the pinned compiler and existing SDK matched the exact released JS model for1080operations. It covers rolling-window limits, completion charging, restart charging including future wall timestamps, rollback, index/Space/fixed/remote fairness, shrinking work lists, rate-limit backoff and recovery. `scheduler-result.json` records source hashes. This code is not included in the application yet and grants no product parity credit.

## Required integration sequence

1. The serialized operation queue core is now implemented and checked; next add and qualify its real native adapters: persist reservation before dispatch, completion before releasing its charge, merge-first409retry, generation/account cancellation, de-duplication and the released consecutive429status. A persistence failure must prevent dispatch and must not wedge the queue.
2. Implement the compatible cipher/envelope and pairing/recovery primitives with published vectors. Preserve scrypt/HKDF labels, AES-256-GCM envelope and version handling. Chromium's custom-KDF API requires an explicit compatibility passkey/review; never use `ForTesting()` in production or bypass that boundary via ad-hoc crypto code.
3. Add a fail-closed key vault using secure OS providers. No plaintext/reversible Linux fallback, renderer-held keys, raw secrets in logs/receipts, or real-account integration before the vault and error paths are qualified.
4. Add generation-bound native transport for Blanc's existing service and encrypted profile-scoped stores. Preserve consent gating, branded-service policy, startup snapshot readiness, safe retraction, write ordering, limits and schema validation. No live network calls have been added.
5. Port the released merge/model and runtime application semantics for tabs, icons, Favorites, settings, sends, shared Spaces and Recently closed; exclude private data and retain selected-tab deferrals. Current native Spaces storage needs an explicit adapter rather than treating its existing format as the released protocol.
6. Connect the released status/pairing/recovery/settings surfaces to redacted native projections and implement v1.45.1 pending-edit/busy/layout/idempotence fixes. Then qualify local-worker failure scenarios and exact-candidate cross-device/platform interoperability.

No new paid service, build system, compiler, SDK or application build was introduced. The development instance and separate Google baseline are unchanged. Full F27/F57/desktop replacement acceptance remains open.

## Owned native worker and shutdown

`native/sync/request_worker.{h,cc}` connects real atomic request-state storage to a Chromium ThreadPool MayBlock/BLOCK_SHUTDOWN sequence and OneShotTimer. It validates request class/item/account generation, posts external completions to the retained reply sequence, latches persistence failure, and explicitly cancels/drains active and waiting queue operations before destruction. Late completions hold only a weak queue reference. The future profile service must retain reply delivery through shutdown, cancel actual URLLoaders and enforce consent/Personal/private gates. Rejected task delivery is a fatal lifecycle-contract violation rather than silently lost completion.

## Compatible native cipher/envelope

`native/sync/protocol_cipher.{h,cc}` uses Chromium AEAD AES-256-GCM and CSPRNG for the released v1 envelope (12-byte IV, separate16-byte tag, no AAD, padded base64). Move-only ProtocolKey clears released/moved storage via SecureZeroBuffer, rejects moved-from use and exposes no serialization/logging API. Native valid-UTF8 including Unicode noncharacters interoperates with exact shipping sync-crypto.js in6cases each direction, including empty/NUL/Unicode/256KiB.12malformed/tampered/wrong-key cases fail closed. The512KiB serialized blob ceiling accepts393162ASCII plaintext bytes and rejects the next byte. Results/source hashes: cipher-result.json; synthetic-only vectors, native envelopes, build/link failures and resolved cached-link commands in outer evidence/native-sync-cipher-20261029.

Native intentionally rejects unsupported versions, noncanonical base64 and authenticated malformed UTF8 rather than permissively decoding them; valid released envelopes remain compatible. This is a defensive parser difference, not proof of full Sync parity. Password scrypt/HKDF, vault, protocol models, pairing, transport, service/profile gates and UI remain unimplemented. The custom scrypt production passkey still requires compatibility review; no testing passkey or raw cryptographic bypass added. No browser build, live account, network, secret-store access or development refresh.
