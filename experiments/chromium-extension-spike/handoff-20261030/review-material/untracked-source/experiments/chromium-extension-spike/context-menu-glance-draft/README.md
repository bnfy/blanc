# Context-menu Glance origin guard

Reference: GitHub latest published Blanc v1.45.1, tag commit `85883b1afa11375e1300130914d6f40c5388af21`, rechecked 2026-10-30. Released `openLinkInGlance` hands external protocols to the OS, rejects forbidden top-level URLs and creates an ungrouped tab with the opener's private state before presenting Glance. Chromium's native new-tab command uses an OpenURLParams carrying the originating frame, referrer and context-menu navigation initiator.

This isolated draft captures a weak window and WebContents, exact frame ID, frame and main-document navigation IDs and URLs. Its guard rejects closed/different windows, wrong profile, inactive opener, pending main-frame navigation, dead/detached/non-primary frame, and changed frame or main document. It is intended for revalidation before navigation and again before attaching a reference after asynchronous work. Header SHA `ad0792fdb273d2d651cfdd9f810a8e02b196dd89959bf7972f752665907eb57a`; implementation SHA `9a1a203ca5082735f9ba68311ff4b2882d3c6ce16a51c976dfe8e5366be8e630`. SDK27.2 syntax-only result `Chromium Preview/evidence/context-glance-origin-v2-20261030/syntax-result.json` SHA `ea604a88bb30d09b3e2151e2928a59f93626067b3014398522ca717273bd8848`. Earlier syntax input retained in `context_link_origin-v1-snapshot.cc`.

The guard is not integrated or exercised against real tabs and is deliberately conservative about focus and same-document URL changes; compare against shipping before considering those refusals final behavior. It does not implement the menu item, navigation, frame policy/referrer handling, external protocols, URL authorization, async frame-store or existing Glance replacement, localization, accessibility or private-tab creation. The caller must retain Chromium's existing navigation and security pipeline and revalidate identity after asynchronous work. Tests must cover regular/private, subframes, navigation and close races, existing Glance, focused split panes, platform-specific UI and localized strings. No parity or release credit.

## Native navigation handoff draft

`context_link_navigation.{h,cc}` calls the originating WebContents' `OpenURL` with a caller-supplied Chromium context-menu `OpenURLParams` and original navigation callback. It requires the context-menu flag and background-tab disposition, rechecks origin after navigation and accepts only an unsplit reference in the same originating browser and exact profile. A presentation callback receives weak reference and captured origin for revalidation after asynchronous work. Origin implementation SHA `4c62a3ca3a20ab4c2ad3a0b86ac2d96636b5c5b12119913fd21a89ce6f6303f1`; navigation SHA `6381ebbcd0bcdd3f6d26d3086025f3463b18abe80f03437fa2dfc0bbf66490f6`. Both pass pinned SDK27.2 syntax-only checks in `Chromium Preview/evidence/context-glance-origin-v3-20261030/syntax-result.json` and `context-glance-navigation-20261030/syntax-result.json`. V2 origin source/header snapshots are retained.

This is not integrated: the native menu must enforce its existing navigation and DLP policy, shipping forbidden-top-level rules and external-protocol consent, and construct the parameters with Chromium's native helper. The callback still needs the actual asynchronous Glance owner, safe replacement/cancellation and localized menu entry. Returned `kOpenedForPresentation` means callback dispatched, not that Glance opened. No GN/link, execution, profile isolation, security, browser or platform test has run.

## Owner lifecycle draft

A separate merged UI source in `Chromium Preview/evidence/context-glance-owner-20261030/staged` adds a context request to the Glance owner. It captures the origin and weak reference across frame-store readiness, rechecks both before and after a pending old-card save, uses the existing replacement machinery and attempts to remove the new card or restore the old card if reentrant work invalidates the origin. Epoch cancellation and a reentrancy guard are included. The v5 syntax-only check passes with pinned SDK27.2 flags. This is unintegrated source, not a runtime pass. In particular, failure, reentrant cancellation, rollback, source/tab destruction, frame-store retries, private profiles, and replacement of an existing card need real browser/lifecycle tests; the reentrant restoration path may still need correction. Menu, policy, localized label and actual callback wiring are not implemented. Do not promote.

## Native menu entry draft

It omits the fork-specific item from Chromium's upstream UMA enum rather than reusing another command's telemetry. Menu source and owner source pass SDK27.2 syntax-only compilation; six label strings exactly match the v1.45.1 source. Manifest SHA `205d8127944834bd124625a6aac651f1b4a7a388195e01cd79e5c939b008f25f`.

This candidate is incomplete and unpromoted. It enables HTTP(S) only; shipping's allowed browser and custom external protocols, denial list, consent and OS handoff still need implementation. The menu is therefore not full parity and must not ship as-is. GN dependency ownership and linker integration, source identity after the pending build, locale fallback, native menu interaction, frame-store lifecycle/reentrancy, extension items, privacy, security, accessibility and all platforms remain unverified. Syntax checks do not test any of those.

## Page-initiated protocol classifier

`context_link_policy.{h,cc}` stages a native classification of page-initiated links into browser-handled, external-consent, denied and invalid cases. It incorporates the exact v1.45.1 dangerous-scheme denylist and forbidden top-level protocols. A standalone native probe linked to the frozen 158 Chromium URL implementation matches the released JavaScript oracle on 57 synthetic cases, including every denied scheme and typical browser and external links. The oracle intentionally applies stricter rejection of unsafe raw text and one-character schemes; those differences and other GURL/WHATWG differences must be reviewed. Source SHA `2756c9fc175f20c542ad0020d4fd593961d9565a96e6ffc2cb691ebdd8578b78`, oracle receipt `Chromium Preview/evidence/context-glance-policy-run-20261030/oracle-result.json` SHA `4cff67f2099e4b1d3afa8d9004f98af0f4baffb794b5fdd8a8f6c9632c0616b6`. The probe compiled two units with preserved frozen 158 cached objects and matching SDK27.0; its original copied receipt incorrectly said three units and is preserved alongside the corrected receipt. The current SDK27.2 syntax-only check also passes.

This is classification only, not menu integration or a permission to open external applications. Chromium's ExternalProtocolHandler may allow previously approved schemes without a new dialog, while released Blanc requires explicit consent for page-initiated external links; use of that handler must preserve or exceed the shipping consent and denylist behavior. Native application-name lookup, per-gesture throttling, exact prompt and localized messages, confirmation, OS launch, URL normalization, browser schemes and end-to-end tests remain open. Do not promote the HTTP(S)-only menu or claim protocol parity.

## URL edge and generated graph audit, 2026-10-30

A new 792-case synthetic raw-URL comparison uses the pinned released JavaScript classification sources and an ICU-initialized native probe built against preserved frozen objects. Receipt `Chromium Preview/evidence/context-glance-policy-edge-audit-20261030/result.json`, SHA `5810c92741b7825836ac18d3b84f193263d9aba1fdb9be5c7c51fa8be8c83eee`. It found 33 differences: the conservative JavaScript-based oracle marks `http:%20` and `https:%20` invalid while GURL classifies them as browser URLs; 31 malformed `filesystem:` strings are accepted by the oracle as browser schemes but rejected by GURL. The staged menu currently disables non-HTTP(S) browser schemes. This is a test-oracle comparison, not proof of actual Electron behavior or an OS/security outcome. Context-menu GURLs are already canonicalized; actual browser behavior for these inputs and valid filesystem URLs requires targeted testing. The first probe lacked ICU initialization and crashed; the first corrected link had a duplicate ICU object. Both failure records are preserved; the corrected link and comparison succeeded.

## Internal utility routing clarification

The released `createTab` called by the Glance dispatcher routes `blanc://` utility hosts to the utility sheet and returns no tab; the earlier mock `createTab` test did not exercise that behavior. `newtab`, `error` and `mahjong` are ordinary internal tab pages, while utility hosts include bookmarks, history, downloads, settings, shortcuts, tab-import and tab-handoff. A blanket conversion of `blanc://` to Chromium URLs would therefore change shipping behavior and potentially expose privileged pages. The draft keeps `blanc:` disabled until native sheet and internal-page handling can be implemented and tested without weakening the page-navigation guard.
