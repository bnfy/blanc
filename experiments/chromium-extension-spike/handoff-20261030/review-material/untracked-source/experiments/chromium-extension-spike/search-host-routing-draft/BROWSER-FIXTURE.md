# Prepared browser fixture

`browser-fixture.mjs` is adapted from the previous selected-search fixture to require the current candidate native source, the exact candidate host and overlay hashes, a successful guarded build receipt and zero-action guard, complete asset and blocker inventories, and fresh profile/label. It is syntax checked but **has not been run**. Its mandatory macOS sandbox denies outbound network, with a local-vs-TEST-NET preflight; CDP interception alone is not treated as a full network boundary. If sandbox preflight or nested Chromium startup fails, retain the failure and do not weaken the boundary.

The prepared portion attempts actual Chromium Settings selection and search URLs for at least two shipping providers, a fresh profile's effective fallback, unsupported-provider retry when a suitable picker option exists, stale document/inactive tab/pending-navigation and A→B→A rejection, local host/IP query/fragment and Unicode-domain navigation, explicit local-file/UNC rejection without transmission, real direct beforeunload veto, and selected private searches with the private marker absent from the closed regular History database. It also attempts to add a synthetic loopback provider through actual Settings controls, then verify new-tab commit after a snapshot-before-result, an intervening A→B→A with the original result epoch retained, and an indeterminate 204 with created identity. Settings selectors and event/lifecycle assumptions have **not** been exercised; any mismatch is a retained failure, not a pass.

`scopedPass` becomes true and the process exits zero only if the required named checks and counts in the script pass and both browser processes exit normally. `complete` remains false even then; this is not full product parity. An optional unsupported-provider picker case is explicitly recorded as missing if unavailable. No controlled OS-handoff delegate, actual native reentrant insertion-observer test, real overlay new-tab transition/accessibility, physical keyboard/VoiceOver, multi-window ownership, hostile frame, shipping-default initialization, Sync/migration, or full platform tests are included. The fixture must not launch until the candidate is reviewed, guarded-built with a zero-action guard, and bound to a real native receipt; use `STAGING.md` for the 158-only procedure.
