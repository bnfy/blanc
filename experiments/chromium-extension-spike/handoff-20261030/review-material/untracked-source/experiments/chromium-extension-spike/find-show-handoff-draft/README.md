# Find show handoff candidate

Shipping reference was freshly checked: GitHub latest release `v1.45.0`, tag commit `6f1bc523d2f0d432d5c4119b9f7ec22a324dbd2d`. The released overlay uses a transient Find capsule. Prior isolated 158 diagnostics showed its host can stop receiving animation frames while hidden, leaving `onOverlayShow` undelivered. Those diagnostics did not establish the foreground user's behavior.

This isolated candidate keeps the normal animation-frame delivery, adds a 250 ms fallback and retries when the overlay subscribes late. A generation token prevents older Find openings from delivering after a close or another mode takes over. It does not guarantee timer scheduling under all suspension policies, does not prove physical focus or keyboard behavior, and is not promoted to a live app. Two host variants preserve separate groups and search+groups base identities. Exact base/candidate/patch hashes and fixture identities are in `receipt.json`.

`node --test handoff.test.cjs` passed ten focused VM tests across both real candidate source variants: regular frame, timer fallback and idempotence, late subscriber, cancellation/supersession, and a subscriber closing during delivery. These are synthetic scheduler checks, not browser parity tests.

One isolated 158 groups-app browser run against a 78-file candidate asset bundle passed after checking the local target document was fully loaded: host entry opened Find; overlay reached Find mode; script-dispatched input `raven` produced `1/3`; Enter advanced to `2/3`; the close button closed the capsule; the owned browser exited 0 and its profile was removed. The exact receipt is `../evidence/find-158-20261029/find-fallback-diag2.json`. This is regular mode with script-dispatched input and host API entry, not physical Cmd-F, macOS-frontmost, private, accessibility, full shipping comparison or Windows/Linux. It uses framework `237242c7...`, not the user's in-memory development instance. The combined host variant has no browser check yet.

Earlier `find-fallback1.json` and `find-fallback-diag1.json` failed waiting for `1/3`, preserving their owned profiles and logs. Diagnostic trace showed native Find sent and returned 0/0; these two fixtures had not waited for the actual test page body to finish loading, which the successful diag2 corrected. Those failures remain evidence and are not silently converted to passes. No user profile, current app, signed candidate or original output was changed. Independent code review and affected private/runtime checks remain before integration or promotion.

## Review follow-up v2

Independent review found two v1 races: an in-flight Find height request could re-show the overlay after Extensions took over, and an obsolete iframe's `onOverlayShow` subscriber could consume the pending handoff after reload. V2 candidates invalidate Find at `showExtensions()` entry, associate each overlay-show subscription with the iframe document current at registration and prune subscribers from old documents before delivery. Both source variants pass syntax checks and new targeted synthetic checks, including delayed height/Extensions and iframe replacement. The initial test-harness run had 12/14 pass; both new Extensions tests failed because the harness assumed one microtask would advance a cross-realm promise. The corrected harness waited for the deferred request; both targeted tests passed. This initial failure is retained in `handoff-v2-initial-failure.txt`. Exact frozen hashes are in `receipt-v2.json`. Independent review is pending.

The v1 groups host additionally passed the affected private Find check (`../evidence/find-158-20261029/find-fallback-private1.json`): all tabs private, host and random unique page in the same non-default context, private theme, loaded-page query `1/3`, Enter `2/3`, close, and owned browser exit 0. The fixture profile was removed only after success. These regular and private browser passes belong to **v1 hash 853a2a9f**, not the changed v2 bytes. No v2 browser run or live promotion has occurred.

## Reviewed v3, affected regular and private checks, and source integration

V3 binds overlay-show subscriptions to the actual iframe document captured by `adapter.js`, rejecting a stale document that subscribes after navigation. Its epoch checks prevent a previously requested panel from taking over after newer Find, and guard close/Extensions height replies. The groups-compatible host includes the already verified snapshot-notice recovery from repo preimage `03cd873b...`; combined host remains a separate unbuilt variant requiring native search support. Independent static review found no blocking defect in these changes. A separate synthetic review noted that if a panel show subscriber synchronously closes or replaces the panel, panel-show RAF code can still focus or apply prefill afterward. Such reentry was not established for the current real subscriber; this remains an explicit limitation and the v3 bytes were not changed to address that hypothetical case.
