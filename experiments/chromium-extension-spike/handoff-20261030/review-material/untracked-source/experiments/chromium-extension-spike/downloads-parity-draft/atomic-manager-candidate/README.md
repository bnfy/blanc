# Atomic DownloadManager observation — review-only candidate

This directory contains **unapplied and uncompiled** Chromium 158 source snapshots and patches. The latest shipping reference remains v1.45.0 / `6f1bc523d2f0d432d5c4119b9f7ec22a324dbd2d`; this lifecycle change is a prerequisite for its Downloads behavior, not feature parity. No UI is registered, no personal profile or app is touched, and the existing native projection and warning fields are preserved separately.

`candidate.patch` modifies exactly five native source files:

1. `content/public/browser/download_manager.h`: a new virtual `AddObserverIfRunning`, defaulting to false for an unsupported implementation. Its contract specifies UI sequence, no callback or nested-task reentrancy and false means not registered.
2. `content/browser/download/download_manager_impl.h` and `.cc`: overrides the method with a check of `shutdown_needed_`, null/duplicate rejection and synchronous ObserverList addition; `Shutdown` and the new method both use a release-mode UI-sequence check. `Shutdown` already flips `shutdown_needed_` before invoking callbacks. The release check changes existing shutdown behavior if a caller violates thread affinity; review every platform and shutdown/test path before adoption.
3. `content/public/test/mock_download_manager.h`: explicit gMock method, default false unless configured. Derived mocks may need expectations or a fake implementation; blindly returning true without actually registering would be invalid.
4. `content/browser/download/download_manager_impl_unittest.cc`: adds an unrun test covering null, duplicate, successful registration, reentrant attempted registration during `ManagerGoingDown`, and a late registration after shutdown. `DownloadManagerShutdownTest` keeps the existing mock-observer/delegate shutdown expectations. More tests, including safe removal during notification, manager destruction, UI-sequence violations and all concrete variants are needed.

An October 29 source-wide declaration search excluding `out/` found the concrete direct subclasses `content::DownloadManagerImpl` and `content::MockDownloadManager`; several tests derive additional mocks from the latter. Default-false virtual behavior protects unenumerated or external subclass implementations, but repository-wide semantic/build validation is still required. `manifest.json` records source and candidate hashes. A read-only `git apply --check` from the 158 source root returned exit 0 after preparation; no application was performed. An earlier attempt with an absolute `--directory` failed; its retained explanation is in `apply-check-invalid-directory.log`.

`service/epoch-service.{h,cc}` is a separate adoption candidate based on the reviewed epoch service; `service.patch` shows its difference. It replaces manager `ScopedObservation::Observe` with the new atomic method and tracks an adopted manager only after a successful non-reentrant registration. It attempts private partial-registration cleanup and retains regular/private profile epoch invalidation and shutdown checks. `service/epoch-service-unittest.cc` proposes three real Chromium/gtest cases for normal teardown, a late rejected manager and private epoch rotation, but is not compiled or run. Native projection and raw warning fields are untouched; no stable renderer classification or actions are added.

**Still blocking:** The trusted caller must establish the supplied profile/manager pointer is live *before invoking a virtual method* and supply only the correct family. `GetBrowserContext`, primary OTR lookup, profile observation, manager removal and other methods could theoretically reenter; the atomic registration guarantee does not cover them. Review actual UI-sequence and observer lifetime, destruction during partial adoption, manager callbacks during shutdown, weak profile checks and the raw_ptr behavior independently. The manager's sequence check does not authenticate a renderer, guard an in-flight raw DownloadItem, verify History load, create opaque document-bound handles or revalidate an async private reply. Mock method behavior and native tests need coverage. Existing observers that use legacy `AddObserver` are unchanged and gain no late-shutdown guarantee. No Safe Browsing, scan/enterprise warning mapping, action or completed-file removal logic is established by this patch.

**Build risk:** `content/public/browser/download_manager.h` is a widely included public virtual interface. Its vtable/API change and all dependent translation units may produce large incremental compile/link fan-out across Chromium and tests; the extra release-mode thread check in Shutdown also needs compatibility coverage. No fresh dry run was run and no reliable action count is available. Before staging, independently review source and all subclasses, preserve outputs/caches and perform the normal guarded dry run; show significant expansion to the owner. Never start a cold build. Any later native unit test, synthetic regular/private browser tests, staged build, zero-action guard and live UI qualification require separate evidence. Electron remains paused, Google baseline separate, latency deferred.
