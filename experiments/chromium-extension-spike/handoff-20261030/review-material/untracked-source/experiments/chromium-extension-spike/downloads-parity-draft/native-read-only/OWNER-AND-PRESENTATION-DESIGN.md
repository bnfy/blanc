# Downloads projection: lifetime and fail-closed presentation design

Status: **design only; projection.cc is blocked, not production-safe or side-effect-free**. `BrowserContextImpl::GetDownloadManager()` (`content/browser/browser_context_impl.cc:288-307`) lazily creates the manager and can call a reentrant delegate. `DownloadItemModel` adds and removes an item observer (`chrome/browser/download/download_item_model.cc:218-230`). Thus checking a caller-supplied token and profile once before these calls does not guarantee either remains valid during or after projection. `Result` contains no owner/epoch; posting it after a private teardown can reveal stale private rows. A scoped service and delivery fence are required; neither exists in this draft.

## Proposed ownership and delivery contract

- A regular-profile-keyed browser-owned service rejects guest/system/enterprise/secondary-OTR contexts at creation; it holds a `base::WeakPtr<Profile>` for the original and, only while genuinely present, its exact primary-incognito child. Use `ProfileObserver::OnProfileWillBeDestroyed` and manager going-down callbacks, with scoped observations and browser UI-sequence enforcement. The service creates independent unguessable generation tokens for the family and each context/manager lifetime, *itself*; renderer/API callers cannot submit the current token. The OTR token changes before teardown/replacement, including same-address ABA; a destruction immediately revokes all private handles, pending replies, and references. Never write OTR metadata or operation identifiers into regular persistent storage.
- Validate trusted primary main frame and its exact committed/visible URL, no pending main-frame navigation, owning window/family and current document generation before scheduling. Capture a weak service, weak regular/private profiles as applicable and immutable family/context/document generation. Discard rather than queue any reply if validation fails. The service owns all observations and invalidates its weak pointers and increments generations on shutdown before dropping callbacks. Do not retain raw profile, manager, model, item or WebContents pointers in a posted closure.
- Because manager lookup may reenter and initialize, bracket it with a projection-in-progress guard and weak/generation checks, including after lookup and before registering/using its observer. Manager ownership/identity and the current child profile must be re-derived and checked again, not inferred from a saved address. A method that reacquires a manager may itself reenter; review this carefully rather than recursively checking forever. Manager teardown increments its generation before observers/handles are released. Explicitly initialize regular History using Chromium's existing core service and observe its actual load/readiness; `IsManagerInitialized()` alone does not prove History is available or complete. Report pending/error when history cannot be demonstrated, never a successful empty list.
- Register observation and maintain a mutation revision for manager/item creation, updates, removal and teardown. Synchronously enumerate only a proven-ready manager, copy only stable per-item data, and detect any revision change, reentrant shutdown or weak invalidation. If a virtual getter or model's observer setup can reenter, do not continue with its raw pointer until lifetime is independently proven. Prefer owned observers and re-resolution by GUID in the exact currently verified manager, not long-lived pointers. The exact no-use-after-free strategy requires implementation and Chromium browser tests; adding weak checks *after* dereferencing a destroyed item is not sufficient.
- Package the immutable projection with internal family/context generation and originating document identity. At final reply on the owner UI sequence, revalidate service, both profiles/manager generations, authorized document/window, policy, visibility and profile relationship. If a projection was serialized or posted, revalidate again immediately before exposing any bytes; drop the entire reply on mismatch, including OTR teardown or a window change. Do not expose the family token, raw GUID, path or private context identifier; use short-lived, unpredictable per-document row handles keyed internally to `{family generation, context generation, GUID}`. A subsequent action re-resolves against the same manager and revalidates independent security policy.
- Reentrancy and copied results remain open problems until implemented and tested; synthetic booleans and matching caller-provided tokens are not evidence of profile ownership. Grouped snapshots spanning regular and private contexts need both captured generations validated together immediately before delivery; fail the whole response if either becomes stale, rather than returning private data under the regular generation.

## State and warning contract

The 158 projection's `state`, `danger_type`, `insecure_status`, and `danger_ui_pattern` are raw C++ integers; existing `downloads-adapter.cjs` only accepts shipping state strings and discards all warning fields. It must not accept a native result until a browser-owned, versioned mapping exists. Prefer C++ enum switch statements tied to the compiled Chromium headers and an explicit *unknown* default over renderer-side hardcoded integer tables. Expose a stable normalized state (`progressing`, `completed`, `cancelled`, `interrupted`, or explicit unavailable) and separate security classification (`safe`, `needs-review`, `unknown`). Unknown state, unknown/future/deprecated enum values, missing fields, inconclusive scans, insecure status UNKNOWN, or inconsistent signals produce `unknown`, never `safe`; safe requires a deliberately reviewed allowlist over all relevant danger, insecure, scan and enterprise-policy signals, not merely `!IsDangerous()` or `DangerUiPattern::kNormal`.

Scanning (`ASYNC_SCANNING`, `ASYNC_LOCAL_PASSWORD_SCANNING`, prompts), failed scan (`DEEP_SCANNED_FAILED`), dangerous content, insecure WARN/BLOCK/SILENT_BLOCK, and enterprise sensitive/block/force-save outcomes must remain visible as explicit non-safe states with useful localized explanations and accessible announcement. A cancelled or interrupted item can still have a warning even when Chromium's UI pattern changes to `kOther`; preserve security independently of download state. Do not substitute “completed” for a warning, and do not hide a blocked row behind an empty list. Route to the existing native warning UI only after that separate action is reviewed. Until trusted policy and outcome observation exist, all capabilities remain empty and Clear Finished disabled; action labels alone are not evidence of authorization. Surface `unknown` as a specific security-unavailable/review message and avoid inventing a verdict. Confirm all copy, six locales, translation fallback, keyboard focus and VoiceOver with the actual native warning flow.

Projection must send only allowlisted schema fields with opaque ID, sanitized basename and HTTP(S) origin; use text nodes/`textContent`, never HTML insertion. Review slash/backslash, drive prefixes, bidi/C1 controls, null/empty/early filenames without failing or hiding unrelated warning rows, and UTF-16 normalization. Define unknown/negative byte counts and clamp or stringify values that exceed JavaScript safe integer limits without fabricating progress. Do not send file paths, credentials, query strings, raw URLs, raw GUIDs or enum diagnostic values that can expose private details. Sorting, history cap, private lifetime and missing-file behavior remain separately unimplemented.

## Required tests before any exposure

Use synthetic regular and primary-incognito browser profiles and controlled downloads: manager-creation delegate reentrancy; profile destruction at each call boundary; manager shutdown during observation; OTR teardown and recreation with same address/GUID but new generation; child-frame, stale main-frame, pending navigation, wrong window, wrong family, guest/system/secondary OTR; deferred, missing and failing History with explicit pending/error; zero rows versus not-ready; mixed snapshots invalidated immediately before delivery; recreated document and operation replay. Exercise state × warning combinations including every 158 danger enum (including deprecated holes), async/failed scans, all insecure statuses, `kOther`, cancelled/interrupted with warnings, and future/unknown values; verify no actions or false-safe label. Test text-only rendering, path/credential omission, bidi/C1, large/negative counters, genuine screen reader and keyboard interaction, translations, live warning transitions and private teardown. Record actual source identities and scoped results; a pure mapping unit test or syntax check is not native/browser/privacy acceptance.
