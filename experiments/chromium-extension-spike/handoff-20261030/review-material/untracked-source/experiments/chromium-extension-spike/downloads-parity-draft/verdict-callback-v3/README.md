# Native download verdict observation — v3 isolated candidate

Latest shipping release/tag verified as v1.45.0 at `6f1bc523d2f0d432d5c4119b9f7ec22a324dbd2d`. This is a separate unregistered source candidate; no original or cloned Chromium checkout, app, profile or cache was changed. See v1/v2 evidence alongside for exact earlier callback checks and preserved review findings.

V2 wraps real URL, client and save-package result callbacks and records raw per-item observations in memory, clearing old generations on no-check/bypass paths and clearing support on invalidation. The original native callback still receives the unchanged result even when recording is unavailable. It exposes no authorization decision and no record from one stage establishes a safe file. An independent review identified a same-item resumption gap: automatic resume can happen synchronously before an interrupted state is externally observed, and the recorder's weak pointers are independent of the item's own per-attempt weak pointers. Therefore old raw observations in v2 cannot be treated as current authorization evidence.

V3 adds a new shared `DownloadItem::Observer::OnDownloadResuming` signal immediately before a resumed request and clears recorder generations on that signal and on observed interrupted/cancelled updates. Its delegate source and `DownloadItemImpl` both passed the 158 syntax-only checks recorded in `syntax-receipt.json`; inherited environment and copied module inputs limit provenance. The state header is byte-identical to v2, whose focused standalone state test passed; this does not execute the new observer hook. The native shared header change can fan out into a large rebuild; no graph plan or build has been run. **Do not integrate this candidate** without independently reviewing observer-list reentrancy, destruction during notification, callback ordering, private/regular lifetimes, user-data ownership, resume/async scan behavior, GN and ABI impact, and real browser tests. A less invasive attempt-invalidation mechanism may be preferable.

Any action decision additionally requires every applicable scan channel, coherent live warning/policy/context, and trusted document/owner checks. Ordinary SAFE vs UNKNOWN results are captured but not consumed. OTR must not persist or leak; regular restored history is still unknown. No file/network/scan callbacks or user profiles were tested.
