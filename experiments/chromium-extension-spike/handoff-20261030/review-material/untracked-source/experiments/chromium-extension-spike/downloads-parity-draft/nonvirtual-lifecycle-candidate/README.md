# Nonvirtual, context-owned Downloads lifetime tracker — isolated candidate

This is an **unapplied, uncompiled, untested review candidate** for the supported Chromium 158 UI sequence. It follows the v1.45.0 shipping product reference but does not implement Downloads UI, private-profile policy, warning decisions, operations or feature parity.

`candidate.patch` changes `content/browser/browser_context_impl.cc`, adds `content/public/browser/blanc_download_lifecycle.h`, and adds three tests to `content/browser/download/download_manager_impl_unittest.cc`. It does **not** alter the existing `DownloadManager` class, virtual interface, vtable or `DownloadManagerImpl` layout. This avoids the specific old-vtable dispatch hazard in the v2 virtual candidate; it does not prove that an arbitrary mixture of old binaries, changed implementation and dependencies is link-safe. `git apply --check` from the unmodified Chromium source root returned 0; no patch was applied. `manifest.json` binds exact original/candidate source hashes, and `candidate.patch` SHA-256 is `afd6bbdde496a210d4b56f7f13c721dc097decb36adc2b79894cec185daf0748`.

On a normal BrowserContext's first manager creation, `BrowserContextImpl` installs a UI-owned `SupportsUserData::Data` / `DownloadManager::Observer` tracker on that freshly created concrete manager **before** calling the potentially reentrant manager delegate. Its token includes the context's `UniqueToken()` and a new per-manager `UnguessableToken`. `ManagerGoingDown` revokes the manager token and detaches the observer; context user-data destruction also detaches it. Two nonvirtual exported helpers retrieve/check tokens only on UI for a live, non-shutting-down context. They never create a manager or return a pointer. An absent tracker, a shut-down manager, a context being destroyed, a test-injected/untracked manager or an off-UI call returns no valid token. `SetDownloadManagerForTesting` does not install a tracker on an externally constructed replacement, avoiding unsafe late adoption. Subsequent default creation after replacement removal obtains a fresh generation. Caller supplies only a live browser-owned context, not a renderer pointer; helpers are not authorization or ownership checks. The existing service is not connected to them.

The test candidate exercises no-token-before-creation, registration before a reentrant delegate, normal manager Shutdown and replacement with fresh generation, and independent regular/private-*like* TestBrowserContexts. `TestBrowserContext` owns a unique disposable directory; a future test runner must still establish an owned user-data root before process initialization. The test does **not** create a true primary-incognito `Profile`, test family ownership, actual delayed renderer delivery, keyed-service shutdown, warnings, downloads, manager callbacks off UI or OS actions. Tests are not compiled or run. Direct TestBrowserContext OTR simulation cannot be claimed as shipping private-profile acceptance.

## Blocking review questions

- The helper is valid only under Chromium's existing **supported UI-sequence shutdown contract**. An independently invoked off-UI Shutdown can race the tracker, observer list and context-owned data; this remains unsolved. Do not claim general atomicity, use as an arbitrary-embedder API, or deploy until the supported boundary and required handling of violations are reviewed.
- `SetUserData`, the manager observer, `ClearAllUserData`, `ShutdownStarted`, reentrant delegate creation, duplicate setup, manager replacement and context destruction need independent lifetime review and synthetic runtime testing. A context pointer passed after its destruction is already invalid; callers must own/revalidate a real weak profile and trusted document before invoking the helper. Do not store raw pointers or deliver private rows without a fresh weak profile, family/context/manager epoch and document recheck.
- A current token establishes only tracker liveness, not manager initialization, loaded History, profile authorization, active manager contents, warning safety, safe filenames, or actions. The token returned during a reentrant delegate is allowed for lifetime bookkeeping but must not be treated as a ready list. No manager pointer or raw GUID is exposed.
- Content public header ownership needs a proper GN declaration and include/layer review (`content/public/browser/BUILD.gn` lists public headers). That is not part of this patch; adding it likely triggers GN regeneration and requires separate approval/review. Test-source linkage and any browser-owned caller also need explicit build definitions and a fresh candidate-aware dry run. No dry run, native syntax compilation, build, or real-profile access occurred.
- Unsupported `MockDownloadManager`, test-injected replacement and downstream manager subclasses remain untracked and fail closed rather than being silently assumed safe. Confirm this behavior is acceptable for test coverage and product lifecycle.

Before trying a build, independently review the source and observer lifetime; produce a reversible, isolated staging/restore plan and show a guarded candidate-aware dry-run scope including GN/header fan-out. A smaller direct link is not yet proven: test runner and TestBrowserContext support objects were absent from the current output during the adjacent fixture cache inventory. Use disposable synthetic profiles only. Preserve user profiles, 157 fallback, existing outputs/caches and Google baseline; Electron remains paused and latency deferred.

A separate reviewer found no new concrete UAF in the supported UI-sequence source path: the fresh manager is observed before delegate reentry, `ManagerGoingDown` makes its tracker inert before test replacement, and context user-data clearing detaches observation and fails closed. The independent reviewer did not compile, stage, launch or edit the candidate.
