# Browser-owned Downloads controller v3 — isolated draft

Reference: GitHub latest release and tag verified 2026-10-29 as Blanc v1.45.0, commit `6f1bc523d2f0d432d5c4119b9f7ec22a324dbd2d`. This is unregistered and not product parity. Frozen earlier candidates remain in `../native-controller-candidate/` and `../native-controller-v2/`.

Independent review found v2 returned `AlreadyIssued` before revalidating an item's lifetime and could retain invalidated handles until a document reset. V3 now re-resolves the family/manager and exact observed item before returning `AlreadyIssued`, and prunes invalidated handles on the next issue or cancel call, outside observer callbacks. It does not enforce a fixed cap on live handles. Its observer tracks removal and destruction; invalidation prevents an old handle being revived by a same-GUID object at the same address. Calls and destruction are UI-sequence-bound.

The Chromium 158 cached-clang syntax-only command and output are in `syntax-command.json` and `syntax.log` (exit 0). An executable of the actual shared `ItemLifetime` template with a fake item passed scope-exit, removal, destruction, and same-address replacement checks with assertions enabled: `xcrun clang++ -std=c++20 -Wall -Wextra -Werror item-lifetime-test.cc -o item-lifetime-test && ./item-lifetime-test`. These checks do not execute the controller, real Chromium item, cancellation, pruning, `AlreadyIssued`, profile teardown or UI. Compiler flags come from the relocated dry-run browser compile command with an isolated candidate header overlay; environment and transitive inputs are not fully pinned. No native build or real profile ran.

Unimplemented and required before exposure: authenticate the current trusted document, owning window/family and user gesture; recheck current item visibility, warning and enterprise policy at issuance and action; observe actual cancellation outcome and support safe retries; validate UI-sequence, observer callback reentrancy, manager/item shutdown and private teardown/recreation with live native tests. The controller denies history items with missing attached context. The shipping sheet and other actions remain unconnected. Live-handle count is not capped; invalid entries persist until next issue/cancel or document reset. Still-live items that leave the capped or otherwise visible list retain their handles and observers until document reset: later integration must reconcile issued handles against the current visible set and bound resource use before exposing the controller. The underlying context-owned lifetime helper remains unapplied and untested in a real browser. Do not register this candidate or claim parity from it.
