# Browser-owned Downloads controller v5 — isolated draft

Latest published release and direct tag verified 2026-10-29: Blanc v1.45.0, commit `6f1bc523d2f0d432d5c4119b9f7ec22a324dbd2d`.

This candidate preserves v4 separately and changes cancellation ordering: verify the bound document without consuming activation, then reject unknown, stale, already-issued, or non-progressing item requests. Only an otherwise actionable cancellation consumes transient activation. After consumption, it checks the same document epoch, re-resolves the family and manager generation, and rechecks the exact observed item lifetime, state and handle before marking issued and dispatching. A genuine document/item race after activation consumption can still consume the gesture and reject; the candidate makes no stronger claim. Cancel remains potentially reentrant: the item and controller are not accessed after `Cancel` dispatch.

`download-controller.cc` SHA-256 `af39ccc0ec3a4dcfd864e1ab7f2352ad013a3b8be09467f2fc98055abf013787`. All five supporting files are byte-identical to the frozen v4 candidate. The Chromium 158 pinned-clang syntax-only check exited 0; see `syntax-command.json` and `syntax.log`. Compiler inputs and inherited environment are not fully pinned. No controller runtime, real document/gesture, real item/lifecycle, browser, native build or product UI test was performed; the order of native side effects and reentrancy still need independent review and executable browser tests. V4's earlier reconciler tests do not test v5's cancellation path and were not repeated.

This remains unregistered, not a shipping authorization boundary, and not a parity claim. Actual owner-window-to-host identity, trusted receiver/document authentication, live current visibility and warning/enterprise policy, profile/OTR manager lifecycle and outcome confirmation are all required before exposure. Reconciliation still relies on complete browser-owned snapshots and does not bound live handles when those snapshots fail. An invalid or stale gesture race after the final check cannot be ruled out without real lifecycle tests. Keep the earlier v4 evidence and source unchanged.

Independent review of the frozen v5 found no new concrete activation-order defect, while confirming owner-window authentication, live visibility/warning/action policy, bounded issuance/reconciliation, and actual iframe gesture behavior remain unverified. It also reproduced a separate snapshot-order defect: a late older complete snapshot can remove handles from a newer snapshot. V5 remains unregistered; see the separately developed v6 candidate for the ordering change.
