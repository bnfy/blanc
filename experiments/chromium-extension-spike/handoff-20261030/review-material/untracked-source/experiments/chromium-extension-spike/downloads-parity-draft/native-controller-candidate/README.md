# Browser-owned Downloads controller candidate

Reference: GitHub latest release and tag rechecked 2026-10-29: Blanc v1.45.0, tag commit `6f1bc523d2f0d432d5c4119b9f7ec22a324dbd2d`. Shipping's sheet offers cancellation for active records, and its manager separates regular and private records by active local profile family. This candidate is an isolated **unregistered and unbuilt draft**, not a parity claim.

`download-controller.{h,cc}` connects the separate context-owned nonvirtual lifetime tracker to a browser-owned per-document handle table. It refuses guest/foreign/secondary-private scopes, does not create a private profile, checks context and manager tokens around lookup, requires an exact attached browser context, rejects stale handles and states other than `IN_PROGRESS`, marks a cancel request before dispatch, and returns `kIssued` rather than claiming completion. Resetting the document revokes old handles. The controller assumes trusted native code authenticated the actual current document/window and passes only a manager-produced GUID for a currently visible row; neither validation is implemented here. It denies items whose attached context is absent, including some history-backed entries. The visibility path, history readiness, native operation observer, UI bridge and private lifetime validation are not connected. It offers only cancel; all other actions and actual sheet display remain open.

This source must not be exposed yet: independent review of object lifetime and reentrancy, manager creation/shutdown, same-address ABA, document replacement, current user gesture and warning/policy behavior is still required. `Cancel` is void and `kIssued` is not evidence that cancellation succeeded; its sticky duplicate suppression lacks a reset/reconciliation flow. Real item removal and context shutdown during `GetDownloadByGuid` or `GetState` require native execution tests. No renderer can be trusted to provide the GUID or a document identity. Scope/profile lifecycle is governed by the separate nonvirtual patch; no product code has been altered by this candidate.
