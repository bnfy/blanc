# Observe-if-running v2 — isolated candidate

This is a separate **unapplied, uncompiled** variant of `../atomic-manager-candidate/`. The v1 candidate adds an unconditional fatal UI-sequence check to `DownloadManagerImpl::Shutdown`; independent review flagged that as stricter than Chromium's transitional `NotFatalUntil::M159` checks, potentially crashing otherwise tolerated callers. V2 leaves `Shutdown` byte-for-byte unchanged. Its new `AddObserverIfRunning` returns false immediately off the UI thread and otherwise tests `shutdown_needed_`, rejects null/duplicate observer and registers synchronously without calling observer code.

This design's shutdown-order guarantee is **conditional**: `Shutdown()` and registration must both execute on the same UI sequence. Chromium declares `BrowserContext` UI-confined (`content/public/browser/browser_context.h:120-121`); `BrowserContextImpl` destruction checks UI before calling manager Shutdown (`content/browser/browser_context_impl.cc:121-153`), test-manager replacement checks UI (`:308-312`), and `DownloadCoreServiceImpl::Shutdown` obtains the manager through its UI-checked context getter (`chrome/browser/download/download_core_service_impl.cc:204-214`). This is useful evidence of the normal Chrome path, not proof for every embedder, unusual test or independently invoked manager Shutdown. An off-sequence Shutdown violates the handshake and can race; v2 does not make it safe and must not be promoted until the thread contract is independently audited and appropriate runtime tests pass. A locking/sequence-relay design would need to solve ObserverList safety, lifetime and private callback ordering; it cannot be assumed safe merely by locking `shutdown_needed_`.

`candidate.patch` modifies six files: the public interface and its existing `.cc` for the out-of-line fail-closed default; manager implementation header/source; shared mock; and manager unit test. It leaves unsupported subclasses fail-closed. Its unrun proposed test adds off-UI registration rejection, multiple observers, self-removal in `ManagerGoingDown`, null and duplicate rejection, registration during shutdown and after shutdown. `service/` is the same unregistered atomic-adoption draft as v1; its separate unrun test candidates include normal/late manager and private epoch rotation. It does not prove that a raw manager pointer passed to Adopt is alive; manager shutdown, profile weak lifetimes, observer teardown, document/family authorization, private epoch delivery, History readiness, warnings and operations remain unresolved.

Read-only `git apply --check` from the Chromium 158 source root passed for this patch. No patch was applied and no native test or production compilation was run. A VFS overlay syntax-only pass with Chromium 158 flags passed for the base implementation, manager, mock, manager unit test, lifecycle service and service unit test; `syntax-results.json`, command receipts and logs bind the inputs. The first syntax attempt failed Chromium style for a nonempty inline virtual default, and its service-test flag lookup failed; both are retained in `syntax-attempt1/`. The default was moved out of line and the relevant test flags corrected. A manifest-regeneration script initially failed on its wrapper key and the subsequent source hash check rejected the partial candidate; `syntax-attempt1/repair-script-error.log` records this, followed by corrected regeneration. `manifest.json` binds the original and candidate source files; `service-manifest.json` binds the patches and service files. `prepare-v1-reference.py` is the preserved v1 generator and is not a v2 regeneration script. Existing v1 source, review and failure evidence remain intact.

The public virtual header can trigger wide compile/link fan-out in the Chromium product and tests; mock subclasses and downstream embedders need audit. The exact scope cannot be inferred from changed lines. No dry run was performed: first complete independent review and a guarded dry run before staging or compiling, and report material expansion. Do not start a cold build. Electron stays paused, Google baseline separate, and latency deferred.
