# Native download verdict callback observation — isolated candidate

Latest shipping release v1.45.0 and direct tag commit `6f1bc523d2f0d432d5c4119b9f7ec22a324dbd2d` were rechecked through GitHub on 2026-10-29. Chromium source preimage SHA-256 `70f35de3851f7565feff0bc2161cfb24414db1a82a24bbb8de3af244afed7d94`. The files here are a standalone candidate; neither the original 158 checkout nor the combined clone was modified.

The candidate delegate wraps actual URL, client-download and save-package scan result callbacks and stores raw enum observations per item and channel, in memory only. The original callback is invoked with the original result, even if the observation weak pointer has expired; disabled safe browsing clears previous observations. Per-stage generations reject old callback updates; removal/destruction detaches the observer and invalidates weak callbacks. Non-UI callbacks bypass recording and still invoke the original callback. The state exposes no positive-safety or action decision, and the candidate is not registered, built or connected to the Downloads sheet. No source URLs, file paths or verdicts are persisted or logged by this implementation. Item user data is never shared across profiles and dies with the item, but actual OTR lifecycle needs browser proof.

**This does not establish a safe download or full applicable-channel coverage.** Disabled, bypassed, unsupported or missing checks can remain unobserved or pending; repeated results and save-package/enterprise channels need actual lifecycle testing. Item and callback semantics, owner shutdown, ID reuse, late scan result and coherent policy snapshots have not been exercised in Chromium. A result of SAFE for one stage is not authorization to open, show or resume. The existing native callback behavior, including any existing ID-based behavior, is deliberately unchanged. The header adds a potential target dependency that GN check/link has not validated. No persistence is provided for regular-history restart; all restored items remain unknown.

`syntax-v4-command.json` and `syntax-v4.log` record the exact 158 delegate dry-run command adapted to syntax-only; it passed using the copied output headers and modules. The inherited environment and transitive inputs were not fully pinned. Initial `syntax-v1-failed.log` preserves Chromium style failures fixed by moving virtual method definitions out of the header; v2/v3 results are retained. `verdict-state-test-receipt.json` records the actual state executable with assertions: channel separation, UNKNOWN vs SAFE raw values, pending/final transitions, stale generations, disabled invalidation, invalid stage and detach. This does not execute real callback wrappers or native item/manager lifetimes. Further independent review, live regular/private scans, unsupported/disabled/fail-open, async/reused IDs, GN integration, link and product checks are required.
