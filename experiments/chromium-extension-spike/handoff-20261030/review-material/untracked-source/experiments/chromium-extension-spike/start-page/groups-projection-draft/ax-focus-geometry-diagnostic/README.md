# Isolated AX window geometry diagnostic

This is a new, unrun diagnostic derived from the separately retained AX observer and its safe fixture. AX1 and AX2 are unchanged. AX2 had confirmed trust and helper exit, but its `window_not_found` result does not distinguish an empty AX window list, missing AX values or a geometry mismatch. It cannot prove that the real browser window belongs to a different process or that geometry is the cause.

The observer still targets only the verified live child PID and checks AX trust without prompting. It adds bounded status codes for AX window list, focused window and focused application; a count of up to 50 windows; and at most eight window position/size status pairs and rectangle vectors. Expected bounds come from the owned fixture's CDP target. AX values outside 100,000 points are discarded. The bridge independently allows only known fixed statuses and bounded numeric vectors, and never records titles, URLs, process names or arbitrary strings. These values can identify zero windows, unreadable geometry or numeric mismatch, not prove which native guard rejected a click. If the window count is greater than eight, returned per-window details are truncated. Matching still examines at most 50 entries and requires one match within three points; it does not weaken the activation guard or select a window heuristically.

Chromium 158's Mac implementation gets native window frame, converts it via `gfx::ScreenRectFromNSRect` to top-left display coordinates and reports DIPs, but this does not establish how the accessibility service will expose this candidate's windows. NativeWidgetMac supports either in-process or remote Cocoa windows, and the actual candidate path has not been observed. Focused-application and focused-window status are only AX indicators; app shims, permissions, caching and sampling remain limitations. The fixture retains its synthetic localhost profile records and intentionally brings its own window forward, which can change the system's foreground application. Do not run without coordinating that effect and confirming isolation.

`python3 observer.test.py` and `node --test bridge.test.mjs` run only synthetic mocks, not AX or a browser. 5 Python tests (including five window geometry modes) and 14 Node tests pass. The fixture, bridge and observer are unstaged; no product build or user profile is touched.
