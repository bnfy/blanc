## Proposed integration

`ui-candidate.cc` and `launch-sunrise-integration.inc` add a trusted Start Page claim with process creation time, the tested process-wide gate, and a `WebContents`-lifetime attempt stored in browser-owned user data. The caller is accepted only after the existing primary-frame and exact committed Start Page checks. Eligibility comes from the actual off-the-record profile, native `WebContents` visibility, and an attached, visible, non-minimized browser widget; a missing process start or local state denies the grant. The isolated candidate uses Chromium Local State for `blanc.prototype.launch_sunrise`, registered false by `prefs-candidate.cc`, to keep this device setting out of profile Sync. It exposes a narrowly scoped Appearance WebUI handler with a managed-preference check. Regular and primary-incognito exact top-level Settings documents can use this device setting; Guest, other off-the-record contexts, untrusted pages and subframes are rejected. `adapter-candidate.js` begins the browser claim before asynchronous initial data reads and fails closed if unavailable. `host-candidate.js` routes normal Settings to a settings hub containing Appearance, Blocking and a link to full Chromium Settings. Private access is a source-level draft and has not yet passed browser testing.

Chromium has no built-in equivalent to the branded Sunrise animation or this device-only option. The prototype ports Blanc's released overlay and adapts Chromium's native Local State preference and WebUI patterns. The settings hub makes the draft Appearance page discoverable without removing the full Chromium Settings link; it still needs actual browser navigation, visual and accessibility review. Owner permits Chrome/Brave familiarity for Settings only. The later staged source and isolated build are identified above; the failed run did not refresh the open development browser.
