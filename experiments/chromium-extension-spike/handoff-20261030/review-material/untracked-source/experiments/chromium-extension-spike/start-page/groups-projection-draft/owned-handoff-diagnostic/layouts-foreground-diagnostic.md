# Remaining regular group layouts and background denial

This separate fixture is prepared and unrun. Ledger's foreground-controlled `fore1` click is existing evidence and is not repeated. A fresh isolated verified candidate/profile tests billboard, shelf and tally using the actual layout buttons and trusted CDP pointer events. Each group click must produce exactly one new indexed click, wrapper call, native request and correlated success/true reply, keep the owned application foreground in sampled checks, and activate the first grouped tab. The fixture uses the reviewed v2 launch and process-birth gates before any input, plus fresh foreground checks before each pointer/key pair and backend tab/group mutation. `Page.bringToFront` and physical input are not used; launching the owned browser itself may change system focus.

It next renames the group through the native host API and waits for the visible tally chip to show the new name. Finally, it switches to a distinct ungrouped control tab and sends `focusGroup` directly through the native WebUI message bridge while Start Page is hidden. It obtains a fresh eligible snapshot immediately before dispatch, verifies hidden visibility in the dispatch turn, and requires the native reply to be false. It rechecks that the control stays active, the Start Page remains hidden and outside visible pairs, and the same group and both regular members exist before and after; the owned process foreground sample must pass. This avoids mistaking a hidden-page adapter short-circuit for native denial. Only the tested native background path is covered; this is not a full background, private or mixed-window parity claim.

Samples are not atomic with CDP input and do not establish native Widget activation at the precise instant. CDP events are synthetic trusted events, not physical input. Proof retains bounded status/group IDs and counts but strips titles, URLs and names; the fresh profile contains synthetic localhost pages. Existing candidate, ledger evidence and earlier failures are unchanged. `node --test layout-evidence.test.mjs` supplies synthetic positive and negative evidence-validation checks, not a browser test. No real run was performed when preparing this fixture.
