# Owned fixture foreground handoff draft

This separate fixture is unrun. It preserves all earlier fixtures and results. It launches the same isolated, inventory-verified candidate with a fresh profile, then pauses for a real OS-level click on that fixture. It does not send a physical click itself or modify product code. The normal native group-focus guard remains unchanged.

The guard verifies that the browser is the Node fixture's direct child, reads its `proc_pidinfo` start seconds/useconds, and pins that birth identity only in memory. Before and after each snapshot it rechecks PID, parent and birth. It binds the owned target to one CDP window ID and one on-screen layer-zero CG window matching the expected bounds. After reporting `handoff:choose_point`, the caller must use a current CUA view to choose an inert blank content point and send `point X Y` in **Quartz global screen points**, not screenshot pixels or page CSS coordinates. The guard requires that point be inset from the frame and checks the front-to-back on-screen CG stack; if any higher window's bounding rectangle with nonzero opacity covers the point, or stack metadata is incomplete, the fixture stops before authorizing a click. The fixture then emits `handoff:point_clear`; only then may the caller click that same point on the owned window and send `resume`. Both inputs share a single 90-second deadline. A closed input, malformed point, timeout, child exit, foreground mismatch or uncertain helper exit aborts with bounded cleanup; uncertain helper exit retains coordination guards.

After `resume`, the guard verifies the same process birth/window/point and requires NSWorkspace foreground PID equality. It repeats this check immediately before the original real group-click dispatch and samples again after it, recording raw native request/reply as before. Foreground is only a sampled indicator and does not prove the internal `Widget::IsActive()` state. CG visibility/occlusion is a geometry snapshot, not an atomic hit test; a different window or user action can race the check and physical click, and window masks or missing system information can differ from bounding rectangles. This is disclosed in the receipt; do not claim that stack checks guarantee the physical event hit the owned window. If CUA cannot safely establish that exact owned point, stop rather than clicking. Never bring the existing user/dev browser forward or act on its profile.

Only the owned fixture's bounds, booleans, status and aggregate occluder counts are recorded. CG window dictionaries for the session exist transiently in the helper; only owner PID is inspected for non-owned windows until a unique owned target is found, then only geometry and opacity for windows above it. No titles, URLs, application names, foreign PIDs, window IDs, process birth or arbitrary system error strings are retained. The fresh fixture profile contains synthetic localhost pages. The inherited `Page.bringToFront` addresses the fixture but can change the system foreground. A CUA click deliberately changes foreground; coordinate this visible effect before execution.

Synthetic only: `python3 handoff_guard.test.py`, `node --test protocol.test.mjs handoff-bridge.test.mjs`. The tests exercise identity, geometry/occlusion, deadlines, privacy and helper cleanup, but do not invoke live libproc, CoreGraphics, NSWorkspace, a browser, CUA or a user profile. Native APIs, coordinate conversion and CUA physical routing remain unverified.
