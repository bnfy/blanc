# Native block-event coverage and proposed qualification

This source trace concerns the current unexposed `native/blocker` working files, not proof of runtime behavior on a particular framework hash. The shipping source is v1.44.1 at `3b0c000b569ee33a1548dd1b9a60817fae9288a6`. No code below is registered, built, or deployed.

| Path | Ownership and existing count | Identity and limitations |
| --- | --- | --- |
| Network URL loader | `Factory::CreateLoaderAndStart` creates one `Request`; its `ShieldCountTicket` is captured from the factory's frame. `Request::Decided` records only engine result 1. | The same object, ticket and loader `id_` cover initial request and redirect hops (`OnReceiveRedirect` updates the request and calls `Gate`). A blocked decision calls `Complete(ERR_BLOCKED_BY_CLIENT)` instead of starting/following the hop. The factory token is scoped to a factory, `id_` need not be globally unique, and the DevTools ID is optional/caller-influenced. None is an established cross-gate identity. A frame-less worker can retain a BrowserContext even though its tab ticket is empty. |
| Response navigation | `NavigationResponseGate` gets a new ticket from the existing primary main frame and calls it on the response decision. | One throttle belongs to a navigation but is not given the loader's `Request` object or its ticket. Normal blocked loaders should not reach this response; cached or prefetched responses can reach it without loader gating. This is a code-path inference that needs a real-browser assertion, including redirect and cache cases. |
| Prerender activation | `ActivationGate` owns another ticket and gates activation of an HTTP(S) prerender. | This is separate from the initial prerender load and response. Its condition exists for activation and has no shared loader identity. A denied initial load should not subsequently activate; revalidation of an allowed load can deny activation. Test this, including a utility failure, before assuming exactly one event. |
| WebSocket | One self-owned `SocketDecision` has one pending callback, timeout and disconnect. Its ticket requires a document-scoped frame. | Its generated token identifies this handshake decision only. A frame-less worker has a weak BrowserContext and no tab attribution. Invalid context/document changes the result to failure; timeout is result -1, not a rule block. |
| WebTransport | One `TransportDecision` follows the same pattern and also checks shutdown/deletion before using the result. | Its generated token is likewise local to one handshake. Frame-less workers have context but no tab ticket. Failure/timeout does not represent a matching block. |

All five call sites invoke `RecordRuleBlock(result)`, which checks result 1, ensures live source and top documents still belong to the primary WebContents, and guards duplicate records **within that ticket**. Therefore that existing counter is not a complete weekly event stream: document checks can reject stale, non-primary or frame-less decisions, while shipping's weekly listener counts before tab lookup. Conversely, ticket-local `recorded_` does not establish cross-object deduplication. The `MaybeProxy` wrapper receives context, frame, factory type and isolation info; it receives no navigation ID. Do not repurpose host/origin, an optional DevTools ID, or the diagnostic `factory_instance`/loader number as a universal identity.

## Candidate event seam

The smallest implementable seam is the *terminal engine decision* in each existing browser-owned object: after the same lifetime checks used to enforce the decision, call a dedicated aggregate sink only when `result == 1`. Use one emitted flag per object so reentrant/late replies cannot write twice; do not derive totals from `ShieldBlockedCount` or store request, URL, origin, tab or token. The `Request` event seam must also check completion and reject a disappeared or shutting-down/deletion-marked context; the transport paths need the same privacy and lifecycle predicate independently of their existing differing network checks. A frame-less worker may count only if its actual weak BrowserContext is live and explicitly a regular non-OTR, non-guest, non-system profile. The context must be checked at the instant of the write. **Never call `GetOriginalProfile()` for an event**; unknown, private and destroyed contexts produce no persistent increment. A normal Start Page may read the aggregate; a private one should neither write it nor receive it. Keep blocking decisions unchanged if statistics are unavailable.

There is no proven common cross-gate identity. A per-object flag protects duplicate callbacks but does not solve cross-gate duplication. The plausible invariant is stronger: an earlier rule block terminates that load before a later gate, and each later gate can count only when it is the first actual denial. It must be demonstrated for each navigation path, including cache, prerender and redirects. Until then keep the event seam in an isolated test candidate; do not deploy it or label totals complete. If an actual double-count path exists, carry an authoritative browser-owned navigation identity through the necessary objects or exclude that path and honestly mark it uncounted; do not infer deduplication by URL or a time window.

The shipping store is device-wide; a local-state aggregate is one possible preservation of regular-profile behavior, provided the regular-context predicate precedes all writes. A profile-pref counter changes multi-profile semantics. Either choice requires explicit lifecycle, write batching and malformed-data handling; this trace does not choose a storage implementation. No private-state migration or copies are authorized.

## Focused production-browser qualification after implementation

Use a fresh owned profile and a version/hash-bound native candidate with real blocker assets. Use an in-memory test observer to identify decision path and outcome; it must be test-only and must not persist URLs or private state. Read the actual Start Page projection and persisted aggregate before/after, not only the observer.

1. Regular allowed resource gives delta 0; one rule-blocked resource gives 1. Renderer crash, shutdown, canceled request, utility timeout, failure and a late callback give 0. Exercise concurrent same-URL requests to ensure each real block counts once.
2. Redirect initial allow to later block gives exactly 1 for that request; include multiple allowed hops, blocked initial URL, redirect replacement rejection and canceled redirect. Verify no subsequent response-gate count after the loader denies.
3. Compare a network navigation, a cache/prefetch-served response and prerender activation: inspect which gates ran and assert one increment for the actual denied operation, including loader denial and revalidation denial. Utility-loss refusal is not a rule block. A different later user navigation is a separate operation, not a duplicate merely because the URL matches.
4. Exercise document and worker HTTP fetches, dedicated/shared/service workers, WebSocket and WebTransport with allowed and block rules. Verify context and count independently of tab attribution; explicitly record any path the implementation cannot identify as regular. No origin-based guessing.
5. Start with a closed regular synthetic profile and stable preferences, run only private rule blocks, close cleanly, then compare the actual stored aggregate bytes and re-opened regular value; neither may increase. Repeat for a simultaneous regular/private window, guest/system where supported, deletion/shutdown and held callbacks. Distinguish unrelated preference metadata writes from any increment and never inspect permanent profiles.
6. Assert Monday-local/day-bucket/rounded-height projection, both DST changes, timezone change, corruption, lazy rollover on read and write, and persistence across clean restart. Check every shipping layout and its private hidden state, including keyboard/VoiceOver as appropriate. Account for local-time changes without using fixed 168-hour intervals.

The existing `shipping-stats.test.cjs` covers released pure arithmetic only. None of these browser tests or a native stats implementation has run.
