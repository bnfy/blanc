# Groups visible-v2 asset-only candidate

`regular2` failed in Ledger after its real ready event: the native `groupsRead` returned the same two-member group found in the host snapshot, and the group row existed in the Start Page DOM, but had no layout rectangle. The root cause is the unchanged prototype stylesheet's `display: none !important` rule hiding `#groupsSection`, `#bbGroups`, `.shelf-card-groups`, `.tally-label-groups` and `#tlGroups`. These are real CSS-hidden ancestors; the evidence does not indicate a `display: contents` hit-testing issue. `regular1` and `regular2` remain failed results and are preserved.

`assets-visible-v2` is a separate 78-file bundle derived from `assets-v1`. Its only change removes exactly those five group selectors from that legacy unavailable-feature rule. The same rule still hides `#remoteSection`, `.shelf-card-blocked` and `.tally-right`; all other assets and native source are byte-identical. `manifest-visible-v2.json` inventories the new bundle, and `asset-only-visible-v2-link.json` binds its sole CSS delta and original manifest to the already verified native build-closure1 receipt/framework. This is a reviewable asset candidate, not a new native build or acceptance. The static test verifies the exact CSS and 78-file delta and preserves the prior bundle and manifest. No CSS-rendering result follows from the static test.

`browser-check-groups-visible-v2.mjs` is an unrun variant of the corrected readiness/visibility fixture. Before launch it verifies the exact asset link, candidate and base manifests, original native receipt, full app inventory and zero guard, source, blocker inventory and every new asset. The result records both manifest identities and the link hash. Its regular scenario uses the real Customize controls and checks group display and activation across all four layouts; its private scenario waits for ready, verifies actual private-group/member presence, performs native `groupsRead` and native focus denial with unchanged active tab, and checks absent chips. Run both separately in fresh disposable profiles after independent review, because the CSS change also affects private-page visibility. Failure diagnostics and cleanup are retained. A real browser, keyboard/VoiceOver and shipping visual comparison remain necessary; private pages still intentionally omit regular groups even though shipping's mixed windows can show them. No rebuild, promotion, open-development-browser restart or profile modification was performed.

Because native group focus intentionally requires an active, visible, non-minimized window, the regular fixture brings only its own Start Page target forward and waits for document focus/visibility before using visible pointer controls. Document focus is not itself proof of native widget state; the real group activation result remains the authority. The fixture remains unrun and subject to review.
