# Isolated Start Page group focus observation draft

This is an **unrun, nonproduction** diagnostic. It derives from the retained `raw1` fixture and does not replace the preserved failure. The new fixture checks `AXIsProcessTrusted` without an authorization prompt before starting its browser. Its AX helper accepts only a live browser PID whose parent is the fixture process and reads window position, size, minimized state, focused-window and focused-application attributes. It matches one window to CDP bounds within three points and fails closed on no match or ambiguity. No AX setter, title or URL lookup is used. The helper never drives a browser. Browser stdout/stderr are discarded, console arguments omitted, and saved proof is redacted for titles, URLs and text. The disposable browser profile still contains its synthetic localhost page records; it is not an AX log or a copy of a user profile. The base fixture still intentionally sends a trusted group click to its disposable browser window; `Page.bringToFront` can change the system foreground application even though it addresses only that owned window. Do not run without coordinating that effect.

`Browser.getWindowForTarget` bounds identify the intended window; it does not expose widget activation. Samples have start/end Python monotonic nanoseconds and markers bracket the CDP click through the observed reply. They are periodic polls, not synchronous reads of the native decision or a continuous proof of key state. AX focus and frontmost status are indicators only: caching, shims, delegate overrides, unsupported AX attributes, coordinate differences and transient switches may leave the result inconclusive. Failures must not be treated as group-product causes or passes. This draft does not assert the exact native rejecting branch. It does not inspect any user window or profile.

Synthetic-only checks passed: five Python cases and thirteen Node cases. They cover trust and ownership denial, ambiguous matching, output redaction, confirmed observer exit and uncertain-exit handling including synchronous stream errors; they do not prove macOS AX behavior. Commands: `python3 observer.test.py`, `node --test bridge.test.mjs`, and `node --check ../browser-check-groups-ax-diagnostic.mjs`. No native AX calls or browser launches are needed for these tests. Before any future execution, independently review TCC attribution and process identity, confirm no active conflicting build/fixture, confirm the existing native output identity and receipt, and perform fresh safe process checks. If trust is unavailable, report that result without prompting. Preserve old raw results and select a new label.

AX1 retained result: preflight passed after the no-prompt trust check; no group click was dispatched. Its receipt did not retain the helper startup phase, PID, failure reason or exit confirmation, so neither helper startup nor exit can be inferred from it. The revised unrun fixture records fixed phase/reason, sanitized first AX sample and confirmed/not-started/uncertain observer cleanup. Existing AX1 evidence is unchanged.
