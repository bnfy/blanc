# Owned foreground group-click diagnostic, version 2

This separate, unrun fixture launches an isolated verified candidate and makes no explicit bring-to-front or physical activation request. Launching the owned browser itself may change system focus. It does not act on the user/dev browser. Its read-only launch gate identifies the unique `about:blank` page in the isolated context, pins the direct-child process birth and requires a unique owned window and NSWorkspace foreground match before creating fixture tabs or groups. If the initial page, window, ownership or foreground cannot be identified, it stops before fixture tab mutation and CDP input.

Each trusted CDP mouse press/release pair and the Escape key down/up pair receives a fresh birth-pinned owned-window and foreground check immediately before the first event. The release follows its matching press to avoid leaving input held. No CDP mouse-move or `Page.bringToFront` is issued. The later group tabs must share the originally verified window. The group action has an additional pre-click sample; its native request/reply and a post-dispatch sample are retained. Foreground samples are not atomic with input and do not prove native `Widget::IsActive()`. A successful result does not establish a physical click or product parity.

The launch gate uses the existing reviewed handoff guard, which obtains an on-screen window inventory and reads transient system metadata for ownership; it retains no foreign titles, URLs, PIDs, window IDs or process birth. Only fixture-owned geometry and aggregate status are recorded. `foreground-v2.test.mjs` checks launch ordering, lack of explicit activation, both CDP input gates and post-click qualification without a browser. This is not an end-to-end test. Earlier fixtures and evidence are unchanged.
