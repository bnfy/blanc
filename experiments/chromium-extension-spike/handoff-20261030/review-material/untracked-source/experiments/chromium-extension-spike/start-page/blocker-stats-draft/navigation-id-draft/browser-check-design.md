# Navigation identity: affected browser-check design

Status: preparation only; no browser check has run and no statistics are counted. The v2 candidate and source identities remain as recorded in `README.md` and `Chromium Preview/evidence/blocker-navigation-id-20261029-v2/manifest.json`. The existing 2026-10-27 navigation-isolation runner exercises real local-server redirects and DevTools replacement in separate regular and private contexts, but its correlation uses DevTools request digests. It does not observe the new factory navigation ID and cannot establish that this candidate propagates it correctly.

A smaller path than building the uncached Chromium `browser_tests` target is an isolated, test-only instrumentation variant of the existing incremental native browser target, subject to an exact dry run before compiling. Reuse the local-server and CDP lifecycle of `evidence/f12-navigation-isolation-20261027/run-affected.mjs` after removing its old `/private/tmp` source/asset assumptions. Launch only a disposable fixture profile with the full verified asset arguments and a dynamically allocated debugging port. Do not reuse or close the development browser. Do not retain test profile contents after a confirmed clean exit.

## Independent comparison

Implement a narrowly scoped browser-side test collector, reachable only under an explicit testing switch in the isolated candidate, which observes the NavigationHandle lifecycle independently of the factory plumbing. Associate the synthetic case with its known frame and live navigation lifecycle, not with URL equality or an ID supplied by the page. Capture the optional factory ID and independently observed handle ID only in memory, compare them there, and return aggregate pass/fail and expected event counts to the test driver. Never return, trace, log, persist, or expose either raw ID, a stable digest, profile identity, real URLs, or a client-supplied request ID. Invalidate test state when the navigation, frame, BrowserContext or test ends. Private tests use a separate off-the-record BrowserContext and must not write counters or regular profile state. The collector must be absent or dormant without the testing switch and must not change blocking, storage, or normal factory lifetime. Review the access boundary before implementation; a simple page-facing WebUI method is not acceptable.

A positive control must fail if the candidate ID is deliberately absent, and a negative control must fail if a wrong, stale, or different navigation ID is supplied; these are essential to prevent a vacuous equality test. Assert every expected event occurs and reject missing observations. Navigation completion alone is not evidence. As upstream caches can bypass a network factory, record whether a factory actually existed for each case rather than declaring a missing event a pass.

## Affected cases

1. In both regular and private contexts, navigate to a local synthetic server with an ordinary main-frame load and a redirect chain. Assert the observed factory ID equals the independently observed live NavigationHandle ID for each created navigation factory; make each case's expected factory count explicit.
2. In both contexts, use the existing CDP Fetch replacement pattern across origins and its restart case. Assert each actual factory and handle comparison and assert no stale factory from an earlier navigation is attributed to a replacement. Preserve the existing request-policy expectations, without rerunning already passed unaffected suites.
3. Cancel an in-flight navigation, start another in the same frame, and destroy a frame or context during an in-flight response. Assert collectors clear and neither late callbacks nor the new navigation reuse old state.
4. Exercise a cached/prefetched response and prerender activation. Observe whether a loader and/or response/activation gate exists and compare identities only where the lifecycle supplies corresponding observations. Explicitly report an activation ID different from a prerender-load ID; never force them to match or infer merging.
5. Confirm subresource and worker factories expose no navigation ID. Run regular and private contexts concurrently and verify contexts never share observations; after private destruction verify no regular-context result or durable state changes.

The diagnostic must not be mistaken for a production statistics implementation. Counting still requires lifecycle-bounded deduplication across loader, response and activation decisions; coverage of failures, redirects, private/guest and worker behavior; persisted migration, write failure and date rollover; and actual Start Page accessibility and behavior. Neither syntax-only evidence nor a passing diagnostic closes those items.
