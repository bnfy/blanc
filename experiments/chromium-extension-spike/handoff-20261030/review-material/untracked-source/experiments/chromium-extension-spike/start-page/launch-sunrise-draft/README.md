# Launch Sunrise grant model — isolated draft

Shipping reference: v1.45.0, `6f1bc523d2f0d432d5c4119b9f7ec22a324dbd2d`, `src/main/launch-sunrise.js` and `main.js`'s first-request guard keyed by WebContents ID. `shipping-launch-sunrise.cjs` is that exact pure source. The draft models the process-wide 30-second grant and one attempt per WebContents lifetime, even across later navigations. A disabled, private or hidden first attempt denies that WebContents without spending the grant; expiry spends the grant; only one eligible page can take it. Backward clock behavior follows shipping. A missing trustworthy process start fails closed.

`compare.cjs` compared 10,007 deterministic multi-page sequences with the released JS, including timing boundaries, visibility, privacy, setting changes, repeated requests and backwards clock movement. `gate_edge_test.cc` also checked a missing start and signed time extremes. The standalone C++ driver was compiled with warnings as errors and both checks passed; receipt and binaries are in `Chromium Preview/evidence/launch-sunrise-gate-20261029/`. This is a pure-model check, not a Chromium browser test or product feature.

Integration remains necessary: establish process-start time before the first browser window without resetting it on late page creation; bind one attempt to actual WebContents lifetime and separately validate trusted document identity; determine real tab/view visibility, non-private profile and setting from browser-owned state; provide a local-only persisted Appearance setting with honest write errors; bind the renderer grant without allowing an untrusted page to spend or forge it; then qualify launch, expiry, hidden and restored tabs, multiple windows/profiles, private pages, reduced motion, restart and actual rendered interaction. The v1.45 renderer candidate is separate. No profile, live browser, native source or build output was changed by this draft.
