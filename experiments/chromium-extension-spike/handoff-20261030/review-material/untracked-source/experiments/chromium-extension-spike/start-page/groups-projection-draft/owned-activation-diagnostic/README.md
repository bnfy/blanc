# Owned fixture activation diagnostic

This separate, unrun fixture investigates whether a normal macOS activation request for the isolated browser changes its real group-click result. It does not change the native active-window guard, product source, the previous fixtures or the AXG1/axs1 evidence. A candidate remains unpromoted.

Before any activation, all three owned fixture tabs must report the same CDP window ID. A fresh helper verifies the target is its parent fixture's direct child, queries the on-screen CoreGraphics window list, and requires exactly one owned, readable, layer-zero window matching the CDP bounds with no truncation. It compares NSWorkspace frontmost PID with that child. If already frontmost it does not send a redundant request; otherwise it rechecks parentage and invokes only that child's `NSRunningApplication.activateWithOptions:0`. It does not hide, close, unhide, request all windows or use deprecated force activation. The helper polls for independently observed foreground; refusal or inability to verify stops before the click. Process start time is not pinned: parent and window checks reduce but cannot eliminate a PID reuse race.

The fixture performs read-only owned-identity and frontmost checks immediately before mouse press and immediately after the real click. Each helper records bounded monotonic start/end timestamps and booleans. The pre-press check must show frontmost. The post-click check is retained even if false or unavailable, alongside the real `focusGroup` request/reply and tab result. A frontmost observation applies only to its sampling interval: it cannot establish click-time or internal `Widget::IsActive()` state. Failed or stuck helper cleanup retains the coordination guards.

No names, titles, URLs or PIDs are saved in diagnostic proof. CoreGraphics returns system-wide window dictionaries transiently in the helper; only the owner PID is read from non-owned entries. The fresh profile still contains its synthetic localhost pages. Bringing the owned fixture window forward and sending the activation request can change the system foreground application; no user window or profile is addressed directly. The separate prior build locks and source/output identity guards remain. Coordinate with the owner before execution if that visible focus effect matters.

Synthetic-only checks: `python3 activate_fixture.test.py` and `node --test activation-bridge.test.mjs` (8 Python and 6 Node tests). They do not invoke macOS activation, AppKit, CoreGraphics or a browser. The native ABI, TCC and real event sequencing are untested.
