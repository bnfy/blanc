# Blanc Chromium desktop replacement: planning handoff

Snapshot: October 30, 2026. This directory is a **planning snapshot**, not an implementation, an accepted build, or authorization to merge or release. Verify current GitHub releases, the branch, and available evidence before relying on it. The owner paused migration implementation while requesting a product specification and implementation plan.

## Objective and product decisions

Replace shipping Electron Blanc on macOS, Windows and Linux with the Chromium fork as soon as a product-complete and safe release is ready. The **latest published Blanc release** is the moving source of truth for behavior, privacy, security, defaults, visuals, keyboard and pointer interactions, and accessibility. At this snapshot it was v1.45.1, source `85883b1afa11375e1300130914d6f40c5388af21`; recheck it. Preserve Blanc's Island and visual identity. The owner allows Chrome/Brave-familiar presentation **only for Settings screens**, while retaining Blanc identity and shipping functionality. Evaluate adapting/rebranding native Chromium features against building custom UI, documenting tradeoffs. uBlock Origin and Widevine are possible exceptions, not waivers.

The owner wants faster, substantial product progress and a useful progress display. Do not equate mock bridges or preview evaluation with product parity. Avoid status-only commits, unnecessary reruns and repeated questions where authorization is already established.

## Claude Code request

Create a reviewable product specification and dependency-ordered implementation plan for the whole desktop replacement. Verify the latest released product and source, inspect the available current code and distinguish missing local evidence from verified absence. Include:

1. A traceable shipping feature/behavior matrix for macOS, Windows and Linux, covering visual, input, accessibility, privacy and security requirements, explicit unknowns and possible exceptions.
2. Decisions for adapting native Chromium versus implementing Blanc UI, with product, security, upgrade/maintenance and test tradeoffs.
3. An honest audit of what is shipped, running, built, merely staged and verified per platform. Do not treat the snapshots here as integrated or claim unavailable evidence was inspected.
4. Prioritized, dependency-ordered vertical slices for a usable Mac build, then Windows/Linux and replacement release. Include migration/session safety, extensions, signing/distribution, updater, fallback and rollback, with objective acceptance criteria.
5. Concrete tasks with components, dependencies, outputs, affected checks, integration risks and opportunities for safe parallel work. Identify expensive build decisions without inventing timelines or weakening protections.
6. An honest progress model distinguishing implemented, integrated, per-platform verified and release-ready, with a process to rebaseline on shipping releases.
7. A short list of genuine owner decisions and a handoff checklist for Codex to follow after review.

Write the specification and plan in durable repository locations and show them for owner review. This is planning authorization only; do not resume implementation, build, change user profiles, sign, publish, merge or release unless separately authorized.
