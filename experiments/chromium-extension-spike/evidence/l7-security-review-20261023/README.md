## Blocking findings

### L7-S1: prototype enforcement/admission hooks remain in the distributable binary

`preview/launcher.c` forwards caller arguments except the two asset-path overrides. In the signed binary, adding `--blanc-ubo-reload-probe` activates the compiled uBO hold path: the fixture receives an actual `ubo-hold-cancel` record instead of the normal Blanc Blocker decision. `probe/report.json` reproduces this without loading an external extension or contacting a public endpoint. The ordinary regular fixture reaches the same local HTTP server.

Source review of `native/blocker/blocker_proxy.cc` shows that the same probe branch skips regular-profile Blanc Blocker WebSocket/WebTransport wrapping and substitutes the experimental uBO request path. `ubo-component.mjs` also installs command-line-controlled component allowlisting/loading; `native/blocker/document_start.inc` exposes the experimental document-start route. These are explicit local-launch opt-ins, **not a demonstrated remote website exploit**. They nevertheless fail L7's written requirement that test hooks be absent from distribution. No such switches or listening debug socket were observed in the default-flags fixture.

**Required repair:** produce a distribution configuration that excludes the experimental component admission, reload/control/document-start and diagnostic identity hooks from its native binary. Keep the research configuration separate. Reject unsupported prototype arguments at the packaged launcher as defense in depth; launcher filtering alone does not remove code reachable through the bundled native executable. Verify both entry points, normal enforcement and artifact identity after the narrow incremental build/sign/notarize step.

### L7-S2: the separate worker-update diagnostic writer persists private metadata

`native/blocker/update_identity.inc`, `BlancUpdateIdentity`, serializes `scope`, request `url`, `storageKey`, registration/version IDs and `private` without refusing an off-the-record context. It is a different writer from `blocker_proxy.cc::Record`, whose private exclusion passes.

`worker-private-ready/report.json` reproduces a private service-worker registration/update on the signed candidate with explicit `--blanc-worker-update-log=<fixture-file>`: the file contains `private:true` and the fixture's scope, script URL and storage key. The plain/private HTTP security suites correctly pass for the ordinary blocker log; those results do **not** cover this separate writer. This is an opt-in diagnostic privacy defect, not default logging.

**Required repair:** reject private contexts before generating the diagnostic identity or serializing/writing any fields, with a regular positive control and a private real-update negative control. The distribution configuration in L7-S1 must also exclude this diagnostic surface. Re-sign/notarize and rerun the affected security tests before requesting L7 acceptance.

## Completed review and runtime coverage

- **Native authority:** inventoried 67 distinct method-comparison names, including internal disk operations, in `source-review.json`. Reviewed Island dispatch, limited new-tab dispatch, tab/group/split/Spaces/history/favorites methods, theme/extension actions, request loader callbacks, and their profile/owner selection. Five critical repository sources exactly match the .15 source tree used for the signed native build.
- **WebUI:** Chromium's WebUI binding check precedes dispatch; the native Island additionally requires its attached `Owner` and exact host URL. Directly navigating a tab to the host URL does not gain that owner. Start-page dispatch authorizes its actual committed document and cannot call Island management. The resource handler serves an exact allowlist with size bounds, and theme image requests require the current regular-profile theme ID. Trusted Types remains enforced with the three exact-static-markup policies; no default/permissive policy was added.
- **Arguments/ownership:** navigation permits HTTP(S); create-tab additionally permits only enumerated internal destinations. Numeric tab IDs and groups resolve in the current window; cross-window close is rejected without changing the other window. Spaces validate structure, sizes, URLs, IDs and profile ownership; names are JSON keys rather than paths. Async handlers use weak owner/profile/document references or owned value snapshots; stale replies recheck the native host. This is source review plus bounded negative coverage, not a proof over every interleaving.
- **Extension permissions:** actions use the native installed registry and active-tab identity and consume transient activation. Theme removal uses Chromium's native uninstall confirmation; managed themes cannot be overridden. Store search/icon requests are bounded, omit cookies, refuse redirects, and accept only the fixed Store/icon destinations. Page permissions in a fresh profile report `prompt` for camera, microphone and geolocation, not pre-granted. No consent prompt was accepted or permanent permission changed.
- **Untrusted content:** ordinary HTTP has no native bridge and cannot acquire it by iframe or fetch. Start-page and detached-host escalation, file/data/javascript/internal-navigation attempts, unknown method, arbitrary icon endpoint, stale tab ID and cross-window mutation are rejected. Theme/extension names and Store result text flow through text nodes; Store branding runs in an isolated world and keeps the real install/remove handlers.
- **Utility boundary:** the blocker bundle digest is checked before sending code to a `kService` sandbox; its Mojo interface accepts only initialization and decisions, with no filesystem/network RPC. The V8 utility is jitless. Request, response and socket lifecycle paths retain fail-closed decisions and bounded callbacks. Previous F12 protocol/lifecycle evidence remains supporting; no additional stress matrix was started.
- **Signed artifacts:** all 17 Mach-O hashes match the prior final audit. Strict deep code-sign verification, stapled ticket and Gatekeeper pass again. The ten identities are preview-specific; no `get-task-allow` or `disable-library-validation` entitlement. No injected dylib, mock keychain, sandbox disabling or diagnostic switches were used in the default-flags launch; no browser TCP listener was observed. Test CDP ports and explicit diagnostic flags belong only to disposable runs, and are not default-launch claims.
